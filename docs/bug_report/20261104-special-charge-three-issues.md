## 一、市二院：低温「双层袋」包材收取口径错误

### 现象

两行低温双层袋，规则价与原单价分别差 **+8.00**、**+12.00**：

| 行 | 包名 | 包装材料 | 件/包 | 原单价 | 规则单价 | 差额 |
|---|---|---|---|---|---|---|
| 9 | 泌尿内镜套件-1套/Z2060 | 铝箔袋200\*600，无纺布-120\*220-60g | 1/1 | 38.00 | 30.00 | +8.00 |
| 10 | 手术室-球内注药-2件/2 | 无纺布-120\*220-60g，铝箔袋200\*600，无纺布-120\*220-60g | 4/4 | 25.00 | 28.00 | +12.00 |

客户口径：

> 市二院低温的双层袋**只收一层包材钱，但是按照内层包材收费**；比如第一个包，就**应该按照低温 200 的包材收费**。

### 对应权威规则（Excel 序号 41 ⑥，第 214 行）

```
⑥ 包名带「/双」 | 额外包低温等离子 |
   费用按标准低温收取，双层带不多收费，一件一包也不收 35，根据纸塑袋宽度收费
```

### 代码与数据现状

- 该条目**尚未在 baseline 落地**：`HRB-2ND.json` 里与 `/双` 相关的只有两条，且都限定 `额外包（纸塑袋）`：
  ```
  20 PRICE_PER_INSTRUMENT 市二院双<3按件5.5加列出的袋封顶16.5  [额外包（纸塑袋）]
  21 PRICE_PER_INSTRUMENT 市二院双≥3按件5.5不加袋            [额外包（纸塑袋）]
  ```
- 因此 `额外包低温等离子` 的 `/双` 行**走通用低温计价**，并按包装材料列的多值组合叠加袋费：
  - `PricingEngine.resolveDoubleBagSizes(...)`（`PricingEngine.java:1728` 附近）把「两个袋规」拆成 outer/inner，**inner 取较小宽度**
  - `configuredBagAddon("inner")`（`PricingEngine.java:2335-2358`）按 inner 宽度取标准价
  - 低温路径未做「双层不另收」的短路，导致包材取的是内层（无纺布 120），与客户要求（按 200 袋）不一致

### 根因

**⑥ 未实现**（历史遗留缺口，此前在规则清单对比中已标注）。系统退化为「通用低温计价 + 内层袋费」，既非「按 200 袋收费」，也未落实「双层不另收」。

### 修复方案（数据侧，不改引擎）

新增 2 条规则（`额外包低温等离子` + `/双`）：

1. 按标准低温袋宽取价（`bagAddon = "outer"` 或按客户确认的 200 袋口径）
2. `skipPackaging = true`（双层不另收、不收 35）
3. 不加 0.3、不做 5.5 按件叠加（该医院 ⑥ 未要求）

> 需客户确认一点：「低温 200 的包材」= 铝箔袋 200\*600 对应档位价（现网低温 20cm 档）。确认后按该档写死或走配置。

### 验证

用行 9/行 10 的真实材料组合回放，规则价应分别等于 200 档低温价（预计 28.00）与 4 件对应价，差额归零。

## 二、骨伤科：钢针 0.3 元被重复加收

### 现象

客户给出的手算：**11 + 5.5 + 0.3 = 16.8**，系统给出 **17.10**（多 0.3）。

### 复现（本地引擎，`HRB-GUSHANG`）

```
输入：富康钢针-6扳手-1/双/z1029，7 件，高温纸塑袋150*260
输出：17.10
规则：[骨伤科钢针先扣扳手按6折算 + 骨伤科双<3按件5.5加内层袋和0.3 + 骨伤科钢针加收0.3 + 纸塑袋费]
notes：… 折算规则叠加固定加价 0 元。 / 骨伤科钢针加收0.3，加收 0.30 元。 / 按规则只加内层纸塑袋标准包材 … 5.50 元。
```

拆解：`2 件 × 5.5 = 11` + `双规则 flatAddon 0.3` + `钢针 EXTRA_FEE 0.3` + `内层袋 5.5` = **17.10**。

### 代码路径

- `PricingEngine.java:560-572`：FOLD/按件规则命中后统一叠加 `foldFlatAddon`（来自 `conditionsJson.flatAddon`）
- `PricingEngine.java:590` 之后：`computeSpecialExtraFees(...)` 再把 `EXTRA_FEE` 规则（`fee 0.3`）加一次
- 两条规则同时命中即**双计**

### 规则现状（`HRB-GUSHANG.json`）

```
20 PRICE_PER_INSTRUMENT 骨伤科双<3按件5.5加内层袋和0.3   conditionsJson: bagAddon=inner, flatAddon=0.3
21 PRICE_PER_INSTRUMENT 骨伤科双≥3按件5.5加0.3          conditionsJson: bagAddon=none,  flatAddon=0.3
13 EXTRA_FEE            骨伤科钢针加收0.3               fee=0.3, keywords=钢针-, exclude=外架钢针
```

Excel 序号 42：

- ① `/双` ＜3：`5.5*件数＋内层包材价格+0.3元`；≥3：`5.5*件数+0.3元`
- ⑤ `钢针-几件 扳手1`：`(件数-1)/6 进位*5.5 + 5.5 + 内层包材 + 0.3元`

两处都写「+0.3」，但对**同一个包（既含钢针又是 /双）**，客户只认一次 0.3。

### 根因

**同一笔 0.3 被建模成两个独立加价**（双规则的 `flatAddon` + 钢针的 `EXTRA_FEE`），交叉命中时叠加两次。

### 修复方案（数据侧优先）

给 `骨伤科钢针加收0.3` 增加排除词：`/双`、`/(双)`、`/（双）`。

- 钢针 **且** /双：由双规则加 0.3 → 只加一次
- 钢针 **但非** /双：仍由 EXTRA_FEE 加 0.3 → 不影响
- 外架钢针：本就排除，保持

### 验证

- 7 件钢针/双：`11 + 0.3 + 5.5 = 16.80` ✅
- 28 件钢针/双：`⌈(28-1)/6⌉×5.5 + 0.3 = 27.5 + 0.3 = 27.80`
- 纯钢针（无 /双）：保持原值

## 三、骨伤科：「包名称带钉」≥10 件未按固定 50 元

### 现象

客户指某「钉」包应为 **50 元**，系统给出 89.20 / 143.20 之类的按件价。

### 对应权威规则（Excel 序号 42 ⑥，第 246 行）

```
⑥ 包名称带「钉」 | 额外包（纸塑袋） | ≥10 | 固定50元
```

### 代码与数据现状

规则存在（`HRB-GUSHANG.json`，priority 4）：

```json
{"name":"骨伤科钉≥10固定50","price":50.0,"keywords":["钉@contains"],
 "excludeKeywords":["钉盒","头钉","拉力钉","空心钉","髓内钉","固定钉"],
 "minInstrumentCount":10,"acceptedTypes":["额外包（纸塑袋）"]}
```

### 复现

```
威客钉-28件        → 50.0  ✅ 命中「骨伤科钉≥10固定50」
拉力钉-1-28件      → 154.0 ❌ 被 excludeKeywords 排除，回落「高温纸塑袋15cm计费」
钉盒-28件          → 154.0 ❌ 同上（钉盒本属 Excel ⑩ 骨科租赁，另有规则）
```

### 根因

**排除词超出 Excel 口径**。Excel ⑥ 只要求「包名称带钉 ≥10 → 50」，并未列出 `头钉 / 拉力钉 / 空心钉 / 髓内钉 / 固定钉` 这些例外；这些排除是历史建模时自加的，导致部分钉包被判为「不适用」而回落标准价。

### 修复方案（数据侧）

- 移除 `头钉 / 拉力钉 / 空心钉 / 髓内钉 / 固定钉`（Excel 未定义）
- **保留** `钉盒`（Excel ⑩「包名称带钉盒」按骨科租赁单独计费，类型也不同：骨科租赁器械包）
- 若客户确认某些钉确有例外，再逐条回写 Excel 后同步

### 验证

`拉力钉-28件`、`头钉-28件` 等应返回 50.00；`钉盒-28件` 仍由 ⑩ 规则处理。
