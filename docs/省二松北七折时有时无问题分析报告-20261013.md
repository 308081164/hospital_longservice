日期：2026-10-13  
范围：客户微信截图 + 对账页「计价规则与流程」+ 当前仓库计价与内勤折扣代码

## 1. 结论

高健的判断是对的：**命中松北特色收费的行不打七折，没命中、走标准灭菌的行才打七折。** 不是同一条规则时好时坏，也不是科室随机。

七折本身没有丢。内勤规则「标准价七折」就是单价乘 0.7，而且不区分这行是不是特色价。挡住它的是特色规则上的 `skipDiscount: true`。编译时写成 `skipHospitalDiscount`，编排器看到这个标记就不再调用折扣。

松北四条特色规则全部带了这个标记：

| 规则 | 类型 | 截图里的表现 |
|---|---|---|
| 省二松北双&lt;3按件5.5加列出的袋 | 按件 | 骨刮匙：规则单价 8.00，账单 5.60，流程里没有「七折」 |
| 省二松北双≥3按件5.5仅外层袋 | 按件 | 同一类，本页未单独打开 |
| 省二松北钉≥10固定50 | 固定价 | 本页未单独打开 |
| 省二松北小腔包按件5.5加5元 | 按件 | 小腔包：规则单价 76.50，账单 53.55，流程里没有「七折」 |

账单上的原单价，正好是系统特色价再乘 0.7：

- 8.00 × 0.7 = **5.60**（骨刮匙，4 包差额 +9.60 = (8.00 − 5.60) × 4）
- 76.50 × 0.7 = **53.55**（小腔包，差额 +22.95）

所以差额不是公式算错，是**特色价停在折前，睿思账单已经是折后**。标准行会把折后价写进规则单价，两边就能对上，例如软式包：折前 8.00，七折后 5.60，差额 0。

## 2. 截图里两类行分别走了哪条路

### 2.1 没有七折：骨刮匙（双头）-1/Z7530

高温室胃镜，额外包(纸塑袋)，材料「高温纸塑袋75*100」。包数 4，账单单价 5.60，规则单价 8.00，原总价 22.40，修正总价 32.00，差额 +9.60。

流程写明：

1. 命中特色规则「省二松北双&lt;3按件5.5加列出的袋」，规则编号 1809。
2. 按包名 `-1` 计 **1 件** × 5.50 = 5.50。表上器械数是 4，计费件数用的是包名里的 1，所以不是 5.50 × 4。
3. 材料列只有一只袋，10cm 袋 2.50，不复制第二只。
4. 5.50 + 2.50 = **8.00**。
5. 后面没有「内勤折扣」也没有「导出阶段折扣」。
6. 字段核对只比较 8.00 和账单 5.60，标成人工复核。

8.00 对上了「5.5 × 件数 + 列出的袋」。5.60 对上了「这个结果再七折」。系统停在第 4 步。

第 14 行是同一条规则、包数 2：单价仍是 8.00 对 5.60，差额 +4.80 = (8.00 − 5.60) × 2。

### 2.2 没有七折：小腔包（手术室）

器械包，账单单价 53.55，规则单价 76.50，差额 +22.95。流程：

1. 命中「省二松北小腔包按件5.5加5元」，规则编号 1811。
2. 13 件 × 5.50 = 71.50，再加规则里的 5 元，得到 **76.50**。
3. 同样没有折扣步骤。
4. 76.50 × 0.7 = 53.55，和账单单价一致，差额就是没打的那三成。

### 2.3 有七折：软式-1/Z1026（ICU）

账单单价 5.60，规则单价 5.60，差额 0，状态无需修改。流程：

1. 未命中特色规则，走标准灭菌。
2. 高温纸塑袋 1 件，含袋费，折前单价 **8.00**，封顶 16.50。
3. 步骤里写着「内勤折扣：标准价七折」和「导出阶段折扣：标准价七折，单价 5.60」。
4. 8.00 × 0.7 = 5.60，和账单一致。

客户说「这个就有折扣」，指的就是这条流程里多出来的第 3 步。特色行的流程在袋费之后直接去做字段核对，没有这一步。

妇科病房，电极-1/Z2090，单包装包（神经阻滞），低温塑袋 200×600。账单单价 24.50，规则单价 19.60，差额 −4.90，计价规则是「标准灭菌」，不是松北特色规则。

## 3. 代码里七折是在哪被跳过的

对账顺序是：内勤计价（命中则直接用账单价）→ 引擎特色价或标准价 → 内勤折扣。松北这几行没有命中内勤计价，所以进了引擎。

引擎命中特色规则时，把规则上的跳过折扣抄到结果上：

```312:317:backend/src/main/java/com/hospital/backend/service/PricingEngine.java
        if (specialPrice != null) {
            expectedUnitPrice = specialPrice.price;
            pricingRule = specialPrice.ruleName;
            notes.add(specialPrice.note);
            skipPackaging = specialPrice.skipPackaging;
            skipHospitalDiscount = specialPrice.skipHospitalDiscount;
```

这个布尔值来自编译后的 `skipHospitalDiscount`，而编译器只看数据库规则的 `skipDiscount`：

```453:458:backend/src/main/java/com/hospital/backend/service/PricingRuleCompiler.java
        if (Boolean.TRUE.equals(rule.getSkipPackaging())) {
            node.put("skipPackaging", true);
        }
        if (Boolean.TRUE.equals(rule.getSkipDiscount())) {
            node.put("skipHospitalDiscount", true);
        }
```

编排器在乘七折之前先看这个标记。为 true 就整段不进折扣：

```91:97:backend/src/main/java/com/hospital/backend/service/ReconciliationPricingOrchestrator.java

        Double priceAfterDiscount = result.expectedUnitPrice;

                && clerkCompiled != null
                && result.expectedUnitPrice != null

                && !result.skipHospitalDiscount) {
```

标准行没有命中特色规则，`skipHospitalDiscount` 保持 false，才会走到下面的「内勤折扣：标准价七折」。折扣计算本身不看规则名叫不叫「标准价」，它只把当前单价乘 `rate`：

```109:113:backend/src/main/java/com/hospital/backend/export/ExportStageDiscountApplier.java
                double rate = params.path("rate").asDouble(Double.NaN);
                if (Double.isNaN(rate) || rate <= 0 || rate >= 1.0) {
                    continue;
                }
                discounted = BillingPolicyApplier.round(baseUnit * rate);
```

内勤原文是「标准价格七折」，倍率 0.7，阶段是账单导出。它没有「仅标准灭菌行」这种条件。现在看起来「只有标准价在打折」，是因为特色行在调用它之前就被标记挡掉了。

松北四条规则在 baseline 里都是 `"skipDiscount": true`。双层袋两条是按件计价、还要加袋费（`skipPackaging` 为 false）；钉和小腔包是跳过包材。四条都跳过折扣，所以只要命中其中任何一条，流程里都不会出现七折。

敷料包是另一条路：编排器在进引擎之前就保留睿思原价，并强制 `skipHospitalDiscount = true`。那是「不再打折」的产品约定，和这次松北特色价不是同一条规则。截图这几行类型是额外包、器械包、单包装包，不是敷料包。

## 4. 这个标记为什么会在

2026-10-12 修松北双层袋时，特意让编排器开始遵守 `skipDiscount`。在那之前，特色规则虽然标了跳过折扣，编排器仍会把七折乘上去。当时的账单样例里，特色价本身还是错的（多算了袋、又封了 16.5），再乘 0.7 会得到 11.55 这类对不上的数，所以把「特色价不再乘七折」当成了修复。

公式改对之后，这个开关还在。特色价现在是折前价：

- 双 &lt;3：5.5 × 件数 + 列出的全部袋
- 双 ≥3：5.5 × 件数 + 较宽的外层袋
- 小腔包：5.5 × 件数 + 5
- 钉 ≥10：50

睿思导出的原单价是这些数再 × 0.7。系统规则单价停在乘之前，差额就稳定地等于特色价的 30%，行会被标成人工复核。

内勤条文写的是「标准价格七折」，可以理解成「只有没走特色表的标准价才七折」。按这句字面，当前代码和条文一致，但和这张账单的原单价不一致。账单更符合另一种读法：特色表上的 5.5、袋费、小腔包加 5 元都是折前价，七折是全院最后一步，特色行也要乘。

两种读法不能同时成立。要和当前账单对齐，就得让这四条规则放行七折；要维持「标准价格」四个字的字面意思，差额就会继续留在特色行上。

---

## 5. 不在这次现象里的情况

- 医院名已经识别成松北，标准行才能套上「标准价七折」。若医院名没对上，标准行也不会出现折扣步骤。截图里软式包有七折，说明这家任务的客户和内勤规则是匹配上的。
- 用户在对账页关掉「内勤折扣」时，标准行也不会打七折。截图里标准行有折扣，说明这个任务没有关这一项。
- 骨刮匙器械数列是 4、计费件数是 1，来自包名 `-1`，只影响 8.00 怎么组成，不决定打不打折。打折开关只看规则上的 `skipDiscount`。

## 6. 修复（2026-10-13 已落地）

研判结论：特色公式价也要打「标准价七折」。改的是松北 baseline，不改折扣倍率，也不改编排器对 `skipDiscount` 的判断。其它医院标了跳过折扣的规则行为不变。敷料包仍保留睿思原价、不再打折。

`backend/src/main/resources/billing-rules/baseline/ERYY-SB.json`：

| 规则 | 改动 |
|---|---|
| 省二松北双&lt;3按件5.5加列出的袋 | `skipDiscount` 改为 false |
| 省二松北双≥3按件5.5仅外层袋 | `skipDiscount` 改为 false |
| 省二松北小腔包按件5.5加5元 | `skipDiscount` 改为 false |
| 省二松北钉≥10固定50 | 保持 `skipDiscount: true` |

钉这一条收费表原文是「固定50元」，类型是一口价。一口价惯例是不再叠加包材和折扣。截图里对不上的是按件公式，不是这条。
