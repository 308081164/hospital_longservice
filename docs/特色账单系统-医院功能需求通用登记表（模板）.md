## 一、使用说明

### 1.1 文档用途（双目的）

| 目的 | 说明 | 主要使用方 |
|------|------|------------|
| **(a) 需求规范化** | 将各医院手工账单流程、Excel 样表、口头规则转化为统一字段，便于开发排期与配置录入 | 业务、产品 |
| **(b) 设计验证** | 对照「代码映射」列，评估当前系统是否已支持、需扩展或不可行 | 开发、架构 |

### 1.2 填写原则

1. **一家医院一份副本**：复制本模板，在「二、医院基础信息」填写该医院名称；多院区按**独立客户**分别登记（参见 FRD 院区约定）。
2. **只填需求，不填实现**：「配置参数/规则描述」写业务规则；「代码映射」由开发填写或标注「待填写 / 待实现 / 不适用」。
3. **是否启用**三选一：`是` / `否` / `不适用`；未确认填 `待确认`。
4. **参考材料**：在「三、参考材料清单」勾选该医院已有的 Excel/Word 样表类型；功能清单中「参考材料类型」与之对应。
5. **验收标准**：尽量可量化（金额一致、行数一致、Sheet 名称一致、汇总勾稽等）。
6. **本模板为空模板**：所有示例行「配置参数/规则描述」均为占位符「待填写」，**禁止**直接当作某医院已确认需求。

### 1.3 功能清单列说明

| 列名 | 说明 |
|------|------|
| **功能项ID** | 全局唯一编号，格式 `FR-Mx-yy` 或 `INT-xx` / `CFG-xx` / `NFR-xx` |
| **功能模块** | 与系统升级模块对齐（M1–M14） |
| **子功能/配置项** | 可配置、可验收的最小功能单元 |
| **代码映射(类/模块/表)** | 现有代码中的类、前端页面、数据库表；未知填「待填写」 |
| **是否启用** | 该医院是否需此功能：`是` / `否` / `不适用` / `待确认` |
| **配置参数/规则描述** | 业务规则、阈值、例外说明（**本模板留空**） |
| **参考材料类型** | 见 1.4 材料类型字典 |
| **验收标准** | 与手工账单/样表核对通过的判定条件 |
| **备注** | 优先级、阶段、依赖、风险 |
