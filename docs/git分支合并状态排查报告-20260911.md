## 四、为何仍会出现「111.xlsx / 人口（1）.xlsx 识别失败」

这不是分支未合并，而是 **解析规则缺口**：

### 4.1 Excel 表头扫描条件过窄

`ExcelBillImportSupport.collectHospitalDisplayNames` 原逻辑只收集含 **「医院」或「诊所」** 字样的单元格。

- `111.xlsx`（冰城医美）：表头区第 9 行有「哈尔滨冰城医疗美容医院」→ **应能识别**（若首行表头定位正确）。
- `人口（1）.xlsx`：若 Excel 内仅写「人口」等简称、不含「医院」→ **不会被收集**。

### 4.2 文件名兜底优先级问题

`ReconciliationHospitalNameResolver` 候选顺序中，文件名推断仍在 Excel 别名之前作为兜底。当 Excel 无全称、文件名为 `111.xlsx` 时，无法解析。

### 4.3 规则匹配仍可能误用文件名

前端 `resolveEntryRule` 在 `hospitalName` 已解析时仍会把文件名加入规则匹配关键词，可能导致错绑规则（本轮已改为：**有 Excel 医院名时不再用文件名匹配规则**）。

### 4.4 本轮增强（代码已改，待部署）

1. 表头区域全量文本 → `CustomerResolver` 别名匹配（「人口」「佳医」等）
2. 文件名降为最后兜底
3. 前端规则匹配：仅当 Excel 未解析出医院名时才用文件名
