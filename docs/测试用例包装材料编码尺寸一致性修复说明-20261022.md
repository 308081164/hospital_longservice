# 修复测试用例「包装材料」编码尺寸一致性 + 格式对齐

> 归档说明：本文原位于 `.trae/documents/`（IDE 会话产物，不纳入版本管理），因含完整根因分析，于 2026-10-22 归档至 `docs/`。

## Summary

修复 `系统内置测试用例` 46 份测试文件里「包装材料」栏与真实账单不一致的问题，核心是**包名中 `/z` 编码与包装材料尺寸/温度错配（124 处）**，并同步对齐材料格式（尾随空格、无纺布 60g 档）。修改集中在生成脚本 `scripts/gen_real_format_tests.py`，改后重跑脚本再生成 46 份文件。

## Current State Analysis（根因）

1. **编码温度错配（主问题，124 处）**：`resolve_material()` 用「包类型」的 `TYPE_PP_TEMP` 决定高温/低温前缀，但真实账单里每个 `/z` 编码的**温度是固定的**（由实际用法决定，非类型决定）。于是产生了真实账单不存在的组合：
   - `z2030`（真实 = 仅低温 `200*300`）被当成高温，生成 `高温纸塑袋200*300`，共 **120 处**。
   - `z2530`（真实 = 仅高温 `250*300`）被当成低温，生成 `低温纸塑袋250*300`，共 **4 处**。
   - 数据依据：真实账单扫描得到 `z2030 → {低温纸塑袋200*300}`、`z2530 → {高温纸塑袋250*300}`；而 `z1026/z1526/z1530/z2060/z3040/z7520/z7526` 等码**双温可用**。
2. **材料格式**：真实账单材料值几乎都以尾随空格结尾（如 `高温纸塑袋75*260 `、`无纺布-90×90-50g `），测试文件无尾随空格。
3. **无纺布克重**：真实账单有 50g 与 60g 两档，测试文件 `W_SPEC` 仅 50g。

## Proposed Changes

全部改动在 `scripts/gen_real_format_tests.py`。

### 1. 把 `Z_SIZE` 升级为 `Z_CODE`（编码 → 尺寸 + 允许温度集合）

用真实账单约定替换现有 `Z_SIZE`（dict `code -> size`）为 `Z_CODE`（dict `code -> (size, set[温度])`）：

```python
Z_CODE = {
    "z1026": ("100*260", {"低温","高温"}),
    "z1029": ("100*290", {"高温"}),
    "z1045": ("100*450", {"低温"}),
    "z1526": ("150*260", {"低温","高温"}),
    "z1530": ("150*300", {"低温","高温"}),
    "z1545": ("150*450", {"低温"}),
    "z1560": ("150*600", {"低温"}),
    "z2030": ("200*300", {"低温"}),
    "z2040": ("200*400", {"低温"}),
    "z2044": ("200*440", {"高温"}),
    "z2045": ("200*450", {"低温"}),
    "z2050": ("200*500", {"高温"}),
    "z2060": ("200*600", {"低温","高温"}),
    "z2530": ("250*300", {"高温"}),
    "z3040": ("300*400", {"低温","高温"}),
    "z7520": ("75*200", {"低温","高温"}),
    "z7526": ("75*260", {"低温","高温"}),
    "z7530": ("75*300", {"高温"}),
    "z7550": ("75*500", {"低温"}),
}
```

### 2. `resolve_material()` 修正温度来源 + 统一尾随空格

- 纸塑袋：温度取自编码自身——`temps = Z_CODE[code][1]`；若 `len(temps)==1` 用该温度，否则回退到 `TYPE_PP_TEMP[typ]`。这样即使 build 层漏改，也不会生成非法温度组合。
- 所有材料值（纸塑袋、无纺布）**末尾追加一个空格**，对齐真实账单。
- 保持 `双层袋` 特殊材料原样（无编码、无空格追加）。

### 3. 修正 build 层编码分配（消除 124 处错配）

- **高温场景 `z2030` → `z2044`（200*440 高温）**：涉及 `build_hospital_cases` 中 `PP_HT`（额外包(纸塑袋)）且 `code="z2030"` 的医院：方南南、东北农业大学、松电慢病、航天风华、道里区妇幼保健院、省妇幼保健院(人口)、祖研南岗、平房区人民医院、九州医院方盘。宽度保持 200cm，`PACK_PRICE[20]` 不变，仅高度 300→440。
- **低温场景 `z2530` → `z2060`（200*600 低温）**：涉及 `build_generic_cases` 中「克氏针 15 件」（免包材，价格 `fold_price(15,25,False)` 与尺寸无关），同时把 `bag` 25→20。

### 4. `W_SPEC` 补齐 60g 档

在现有 50g 基础上增加 60g 键：`w5060/w6060/w7060/w9060/w12060/w15060`，值形如 `无纺布-60×60-60g`。当前无测试用例引用 60g，仅补齐映射供后续使用。

## Assumptions & Decisions

- **不扩充到真实账单全部 197 种规格**：测试文件用于校验计价规则，仅需保证「已用规格的编码↔尺寸↔温度正确 + 格式对齐」，不新增覆盖所有尺寸的用例（用户未明确要求扩充）。
- 「规则说明」列（R 列）与负向红色标注保持现状（在基础表 A–Q 之外，不影响对齐）。
- 科室分组（手术室/处置室/消毒供应室）保持不变。
