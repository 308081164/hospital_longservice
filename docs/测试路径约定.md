# 计费测试路径约定

> 本约定用于区分两套**完全不同**的验收口径。任何「严格测试 / 同步检查 / xx 家医院」需求，必须先判定走哪条路径，**禁止混用材料、医院清单或报告文件名**。
> 本文件与 `.cursor/rules/billing-test-paths.mdc` 内容一致，后者对 AI 助手强制生效。

## 路径 A — 特殊计价医院逐家严格测试

**何时用：** 「N 家特殊计价医院严格测试 / 逐家严格对账 / 升级前后能力对比」。

| 项 | 约定 |
|----|------|
| 医院清单 | `BillingSeedMigrationRunner.STRICT_KEEP_CODES`（历史 22 家）+ 后续正式新引入的特殊计价院（当前 +4：HULAN-RM / XINFA-HSZ / YUANDONG-XN / ZUYAN-SF） |
| 材料 | 与 **2026-08-27 基线报告**（`测试用例/特殊收费v8严格Excel对账报告-20260827.json`）相同的 raw+proc 账期与文件；新引入医院只在 `测试用例/<院名>/` 下按同一规则（raw vs proc 成对账期）扩展材料 |
| 账期 | **锁定基线月份**（见 `测试用例/特殊计价严格测试-材料锁定.json`），禁止擅自改用「最优账期」；只有基线标记 SKIP（缺材料）的院才允许按 7→5→4→8→6→3 fallback |
| 脚本入口 | `scripts/special_v8_strict_excel_audit.py`（`./bin/hospital-cli audit strict-v8`） |
| 报告命名 | `测试用例/特殊计价严格对账报告-YYYYMMDD*.{json,md}` |

**禁止：** 用 `verify-billing-seed.sh` 的 EXPECTED 26 清单、或 `billing-seed-26*` 报告当作本路径结果。

## 路径 B — 规则 / billing-seed 同步检查

**何时用：** 「规则是否完全同步 / billing-seed 覆盖 / 种子落库核对 / 与 manifest 对比」。

| 项 | 约定 |
|----|------|
| 清单 | `scripts/verify-billing-seed.sh` 的 EXPECTED 26 + 铂康参考 42 等 |
| 手段 | `verify-billing-seed.sh`、`hospital-cli rules compare`、DB marker / 规则字段核对、simulate spot-check |
| 报告命名 | `billing-seed-*`、`billing_rules_parity_*`、规则对账 JSON |

**禁止：** 把路径 B 的医院集合拿去跑 Excel 严格对账，再声称「特殊计价 N 家能力退步/进步」。

## 快速判别

- 问的是「算价对不对、和客户处理后 Excel 是否一致」→ **路径 A**
- 问的是「种子/规则有没有录进去、和清单是否一致」→ **路径 B**
- 两者都要做时：分开跑、分开写报告、分开汇报，标题写明路径名

## 历史背景

- **2026-07-18**：`verify-billing-seed.sh` 引入 EXPECTED 26（billing-seed 种子覆盖清单，路径 B）
- **2026-08-27**：生产收敛到 22 家特殊计价客户（`STRICT_KEEP_CODES`），同日输出 v8 严格对账基线报告（路径 A 的基准）
- **2026-08-30**：v17 特殊收费(17) 规则录入，新引入 4 家（HULAN-RM / XINFA-HSZ / YUANDONG-XN / ZUYAN-SF）；同日曾误用 billing-seed 26 清单跑严格对账（`billing-seed-26严格验证-20260830*.json`），导致口径混淆——本约定即为此而立
