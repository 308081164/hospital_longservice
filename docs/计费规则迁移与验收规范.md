# 计费规则迁移与验收规范（强制）

> 版本：2026-09-02 制定。背景：2026-08-30 ~ 09-02 连续发生多起「规则未按 Excel 完整/正确落库」事故
> （胶帽/根管锉词中失配、总工会固定价缺失并多加包材、人口垫片规则缺失、水管膜片关键词静默丢失等）。
> 本文档是杜绝此类问题回潮的**标准化操作守则**，所有计费规则变更必须遵守。
> 相关：路径约定见 `.cursor/rules/billing-test-paths.mdc`；大文件处理见 `.cursor/rules/no-huge-file-reads.mdc`。

## 一、事故根因分类（五类，均已有对应闸门）

| # | 根因 | 历史事故 | 对应闸门 |
|---|------|---------|---------|
| R1 | Excel「包名称带X」（包含语义）被建模为 exact_token 词边界匹配，CJK 邻接变体词中失配 | 胶帽组件-25件、加长根管锉-6 | G2 关键词失配复扫 + G4 Excel 对账 |
| R2 | Excel 段落/条目迁移时漏迁（整院缺失或单条缺失） | 总工会 14 条固定价、人口垫片 | G4 Excel 对账（逐条） |
| R3 | 种子 ruleUpdates 补丁被 manifest 生成器静默丢弃（目标规则由字母序靠后文件/硬编码创建） | 水管膜片（12-sync 补丁丢失 15 天） | G1 生成器丢弃硬闸门 |
| R4 | 生产手工建规则绕行 manifest，配置违背惯例（如 FIXED_PRICE 未 skipPackaging） | 总工会固定价多加 8 元包材 | G3 rules compare + 惯例检查 |
| R5 | 用户侧 Excel 已更新但仓库内副本未同步，按旧版迁移 | 人口段新旧版本差异 | G0 Excel 版本确认 |

## 二、规则迁移标准流程（六步，缺一不可）

1. **G0 Excel 版本确认**：迁移前向用户确认 Excel 文件路径与版本（`docs/source/` 内副本须与用户手中版本逐行一致）；用户发新 Excel 后先替换仓库副本再迁移。禁止凭截图以外的旧副本臆测。
2. **逐条建模**：按 Excel 段落逐条建规则，每条记录：关键词、匹配语义（见第三节判定表）、价格公式、分段阈值、温度域、包材约定（skipPackaging/skipDiscount）。合并单元格须按区间向下填充后解读。
3. **落库**：**仅**编辑 `billing-rules/baseline/{CODE}.json` → `python3 scripts/refresh_baseline_index.py` → `python3 scripts/baseline_to_manifest.py --write` → PR。**禁止**手改 `billing-rules-manifest.json`、新增 `phase-*.json` 种子或依赖 manifest reconcile 写 DB。UI 改规则后须 export 回 baseline 再发版。
4. **G1 基线校验**：`python3 scripts/baseline_to_manifest.py --check` 零 diff；`./bin/hospital-cli rules verify --all --fail-on-drift` 零漂移。
5. **G2+G4 验证**（见第四节）全部通过后，**G3** `hospital-cli rules verify --all` 零漂移方可提交。
6. **部署后生产验证**：部署完成后在生产跑 rules compare + 关键包名 simulate 抽查，确认与本地一致。

## 三、关键词匹配模式判定表（严格按 Excel 措辞，禁止自行发挥）

| Excel 措辞 | 建模 | 说明 |
|-----------|------|------|
| 包名称带"X" / 名字带 X | 关键词 `X@contains`（词级包含） | 规则级 keywordMatchMode 保持 exact_token 管文本域，词级 @contains 管包名包含 |
| 指定完整包名（如「抛光车针盒6件盒1/Z1026」） | exact_token，关键词含完整名称（编码/件数变体按真实账单形态补齐） | 社会康复 14 条固定价先例 |
| 「针多少盒1」模式词（针盒针公式） | exact_token + 模式词（如 `针`），**不得**改 contains | 过匹配会误伤车针排/持针器等（0831 报告⑦先例） |
| 规则里非 Excel 条目的通用小件词（车针/探针/球钻等） | 保持 exact_token | 仅 Excel 明确「包名称带X」的词才加 @contains |
| 非 FOLD 规则（FIXED_PRICE/EXTRA_FEE/PRICE_PER_INSTRUMENT） | 缺省 contains（组合文本子串），与 Excel 包含语义一致 | 无需 @contains 后缀 |

**FIXED_PRICE 惯例（强制）**：`skipPackaging=true` + `skipDiscount=true`（固定价一口价，严禁再叠加包材/折扣）。违反即 R4 事故。

## 四、验收闸门（G1-G4，全部通过才算完成）

| 闸门 | 命令/手段 | 通过标准 |
|------|----------|---------|
| G1 生成器丢弃闸门 | `python3 scripts/baseline_to_manifest.py --check` + `python3 scripts/billing_rules_manifest.py --write`（遗留路径） | manifest 与 baseline 零 diff；生成器零 FATAL |
| G2 关键词失配复扫 | `python3 scripts/tmp_keyword_gap_scan.py`（复刻后端 exact_token 语义，全规则关键词 × 真实账单包名） | 零词中失配（或逐项确认系故意排除） |
| G3 清单对账 | `./bin/hospital-cli rules verify --all` | 0 漂移（missing/changed/extra） |
| G4 Excel↔manifest 逐条对账 | 全量对账（方法见 `测试用例/excel-manifest-parity-audit-20260902.md`：openpyxl 解析合并单元格 → 逐院逐条比对关键词/语义/价格/分段/温度域/包材约定） | 29 家逐条 PASS 或每项差异有用户书面确认的口径决策 |
| G5 基线回归 | 路径 A 严格对账（受影响医院账期） | 无新增差异 |

**变更涉及 FOLD 关键词/匹配模式时，G2 必跑；涉及任何规则增删改时，G1/G3 必跑；每次 Excel 版本更新后，G4 必跑。**

## 六、PR 合并前检查清单

```bash
python3 scripts/refresh_baseline_index.py
python3 scripts/baseline_to_manifest.py --write
bash scripts/assert_no_new_phase_seeds.sh
./bin/hospital-cli rules verify --all --fail-on-drift
```

部署后生产验证：`rulesBaselineHash` 与 `index.json` 一致，`rulesVerifyStatus` 为 ok。

## 五、禁止事项

- 禁止凭推测优化规则（Excel 没写的不做）；关键词一个标点都不得偏离 Excel。
- 禁止在生产手工建/改规则绕行 baseline（下次部署 baseline sync 会 purge 孤儿规则）。
- 禁止把路径 B（billing-seed 同步检查）的医院集合用于路径 A（严格 Excel 对账）结论。
- 禁止在生成器出现 FATAL 时通过删除补丁、改规则名等方式压制告警。
