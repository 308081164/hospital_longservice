# 附一内勤折扣与账单分科室问题分析及改动方案

日期：2026-10-22。对照客户内勤规则 Excel 行 13 截图（医院「黑龙江省中医药大学附属第一医院」）、仓库 `ZYY-D1` baseline，以及既有附一分科室导出配置。只写分析与改动方案，不改业务代码、不 commit、不部署。

医院编码：`ZYY-D1`（全库别名含「黑龙江中医药大学附属第一医院」「中医附一」「附一」等）。对账叠折在 `billing-rules/baseline/ZYY-D1.json`；导出布局在 `clerk-rules/baseline/ZYY-D1.json`。

---

## 结论

**折扣表缺口。** 当前仓库已落地的是 commit `3ef3640b` 的简化口径：两条 `DISCOUNT`——「附一对账八折」对所有行始终 ×0.8；「附一对账九九九折」用 `pieceTierDiscounts`（`minPieces=1`、`maxPieces=2`、`rate=0.999`），仅在单包器械数 `billingPieces` &lt; 3 时再叠乘。件数口径是**单包** `billingPieces`（`PricingEngine.materialBillingCount`），不是整行多包合计。截图整表还按**包类型**分支：缺「额外包（无纺布）&lt;3 固定 13.2」、缺「敷料包（纸塑袋）件数无关只八折」、缺「单包装包（等离子/EO）与额外包（低温等离子/ETO）件数无关也叠 0.999」、缺「敷料包（无纺布）件数无关叠 0.999」。现行策略无 `acceptedTypes`，引擎对 `DISCOUNT` 也只按温区过滤，所以这些类型条件全部未落地。

**导出不分科室原因。** 不是「规则里没写分科室」。`clerk-rules/baseline/ZYY-D1.json` 已是 `billLayout=dept_split` + `fuyi_extended_11col`；历史种子与 7 月 smoke 导出也能打出 40+ 个科室 Sheet。附一原始账单本身就是按科室多 Sheet，导入会把工作表名写入 `sheetName`，不是「导入时没识别科室」。若客户看到的是一张合并表，更像是**运行时没有走到 dept_split**：医院名未解析到 `ZYY-D1` / 模板 `column_mapping` 丢失 `billLayout` 时退回 `auto`，而附一单月行数常 &gt;1000（6 月约 2200 行量级），`auto` 在多 Sheet 且行数超过阈值后会走 `createCombinedBillWorkbook`，把所有科室写进一张「合计」表。需要先在导出预览/校验里看 `billLayout`、`distinctSheetCount`、`layoutMismatchWarning`，再决定是补种子/解析还是修预览合并路径。

## 2. 对照现状：`3ef3640b` 与截图差在哪

### 2.1 已落地（仓库 baseline，生产是否已部署需环境核对）

文件：`backend/src/main/resources/billing-rules/baseline/ZYY-D1.json`。

| 规则名 | policyType | 匹配 | 费率/分段 | 状态 |
|---|---|---|---|---|
| 附一对账八折 | DISCOUNT | `scope.temperature=ANY`，无包类型 | `rate=0.8`，始终 | 已在 baseline（`3ef3640b` 保留） |
| 附一对账九九九折 | DISCOUNT | 同上 | `pieceTierDiscounts`：1–2 件 `rate=0.999` | 已在 baseline（`3ef3640b` 新增分段） |

clerk 侧整院八折 / 旧复合调价已封存（`isActive=false`），对账叠折只走 billingPolicies，与 clerk notes 一致。

件数：`BillingPolicyApplier.applyBillDetailDiscounts(..., billingPieces, ...)`，由 `PricingEngine` 传入的单包件数，**不是**行上「包数 × 单包件数」的整行器械总数。

### 2.2 与截图的缺口

| 截图要求 | 现行行为 | 缺口 |
|---|---|---|
| 仅列出的高温类包类型才进件数分支 | 所有类型都叠八折；&lt;3 再叠 0.999 | **缺包类型 `acceptedTypes`** |
| 额外包（无纺布）&lt;3 → 固定 13.2 | 仍走 ×0.8×0.999（无固定价档） | **缺固定价**；`pieceTier` 虽支持 `fixedUnitPrice`，但未配置且无类型门控 |
| 敷料包（纸塑袋）任意件数只 ×0.8 | &lt;3 时仍叠 0.999 | **缺「件数无关只八折」** |
| 等离子 / EO / ETO / 低温等离子任意件数 ×0.8×0.999 | ≥3 时只有八折，不再叠 0.999 | **缺「低温类件数无关叠 0.999」** |
| 敷料包（无纺布）任意件数 ×0.8×0.999 | 同上一行，≥3 丢 0.999 | **缺** |
| 额外包（无纺布）≥3 → ×0.8 | 现行始终八折，这一档碰巧接近 | 需与固定 13.2 分支成对配置，避免 &lt;3 误折 |

另：`productRules` 里有一条停用的「球内注药3件最低把价」`price=13.2`，与「额外包（无纺布）&lt;3」不是同一条，不能当本缺口已实现。

### 2.3 引擎能力边界（改规则前必须知道）

- `BillingPolicyApplier.findScopedDiscountPolicies` 目前只按 `scope.temperature` 与 `skipWhenFixedPrice` 过滤，**不读 `acceptedTypes`**（`type` 参数只用于拼温区字符串）。
- `pieceTierDiscounts` 已支持 `fixedUnitPrice`（可做 13.2），但必须先能按包类型命中。
- 包类型等价比较已在 `BillingConditionEvaluator.matchesAcceptedPackTypeList` / `PackTypeRegistry`（全半角括号等），productRules 在用；DISCOUNT 策略层尚未接上。

因此：只改 JSON、不改 `BillingPolicyApplier`（或等价门控），**无法**完整表达截图按类型分支。

## 3. 对照现状：导出账单「没有分科室」

### 3.1 配置已经要求分科室

| 位置 | 内容 |
|---|---|
| `clerk-rules/baseline/ZYY-D1.json` | `EXPORT_LAYOUT`「附一11列分科室账单」：`billLayout=dept_split`，`billColumnLayout=fuyi_extended_11col`，`d8DisplaySource=hospitalName`；另有 `MONTHLY_SUPPLEMENT_REPORT` 分科室汇总 / 物流分摊 |
| 历史种子 `phase-export-dept-split-20260728.json`（已 archive） | `ZYY-D1` 模板同为 `dept_split` + 11 列 |
| 对照院 | 电力 `ZY3-DIANLI`：无 `billLayout`，主要靠 `keepColumns=["器械数"]` 加列；南岗妇产 `NG-FUCHAN`：`keepColumns` 包装材料+器械数。附一是**强制多 Sheet**，不是「只加科室列」 |

导出链路：`HospitalReconciliationServiceImpl.generateBillExportBytes` → `ClerkExportLayoutMerger.mergeIntoRequest` / `merge` 覆盖布局 → `BillExportLayoutResolver.useDeptSplitWorkbook`：显式 `dept_split` 时恒为多 Sheet；`createBillTemplateWorkbook` 按行上 `sheetName` 分组建 Sheet。

### 3.2 导入有没有科室

附一原始表（如 `测试用例/.../原始表格/附一6月账单.xlsx`）约 42 个科室 Sheet；导入 `ExcelBillImportSupport` 用工作表名作 `sheetName`（合并单表才走行内科室标记）。历史 smoke `zyy-d1-july-export-*.xlsx` 亦为约 45 个科室 Sheet。  
**结论：材料侧是分科室的；「导出一张表」不是导入丢了科室列，而是导出布局落成了合并模式，或 Job 上 `sheetName` 被收成单一值。**

### 3.3 为何仍可能导出成一张

1. **`billLayout` 未变成 `dept_split`（最可疑）**  
   医院名解析不到 `ZYY-D1` → clerk 合并不生效；或 DB `export_template.column_mapping` 无 `billLayout`。此时布局为 `auto`：`distinctSheets>1` 且行数 **≤1000** 才分 Sheet；附一单月常 **&gt;1000**（6 月各 Sheet 行号合计约 2200）→ 走 `createCombinedBillWorkbook`，全部写入一张「合计」。

2. **`dept_split` 已配置但 Job 只有 1 个 distinct `sheetName`**  
   `ExportEngineServiceImpl` 校验里有 `layoutMismatchWarning`（期望 multi_dept 但 `distinctSheetCount≤1`）。此时即使强制 dept_split，也只会产出一个 Sheet。需查该 Job 行数据，不是改 clerk JSON 文案。

3. **预览标签与真实导出不一致（次要）**  
   `buildExportProfileFields` 主要读模板 `column_mapping`，未必合并 clerk；真实导出路径会 `ClerkExportLayoutMerger`。UI 若只看预览，可能误判；以实际导出文件 Sheet 数为准。

4. **不是「丢了科室列」**  
   附一 11 列布局本身按科室拆 Sheet，表内不再单独靠「科室」列区分；合并模式下也没有把科室展开成多 Sheet。

## 4. 改动方案

### 4.1 对账折扣（billingPolicies）——建议条目表

改 `backend/src/main/resources/billing-rules/baseline/ZYY-D1.json`（必要时同步 `BillingPolicyApplier` 对 DISCOUNT 增加 `acceptedTypes` / `packTypeMatches` 过滤）。类型名写入全角括号，匹配层继续兼容半角。优先级按「更具体优先」。

| # | 规则名（建议） | 匹配条件 | 费率 / 固定价 | priority | 相对 `3ef3640b` |
|---|---|---|---|---|---|
| A | 附一额外无纺布&lt;3固定价 | `acceptedTypes`含「额外包（无纺布）」；`billingPieces` 1–2 | `pieceTier.fixedUnitPrice=13.2`（或 FIXED_PRICE + skipDiscount） | 5（最先） | **缺，需新增** |
| B | 附一对账八折（通用包类型） | 额外包（纸塑袋/无纺布）、器械包（ZSD）、器械包、单包装包、敷料包（纸塑袋/无纺布）、单包装包（等离子/EO）、额外包（低温等离子/ETO）等截图所列 | `rate=0.8` 始终 | 10 | **收窄类型**（现行无类型门控） |
| C | 附一九九九折·件数&lt;3 | 额外包（纸塑袋）、器械包（ZSD）、器械包、单包装包；`billingPieces` 1–2 | `rate=0.999` | 20 | **收窄类型**（现行打全部类型） |
| D | 附一九九九折·件数无关 | 单包装包（等离子）、单包装包（EO）、额外包（低温等离子）、额外包（ETO）、敷料包（无纺布） | `rate=0.999`（无件数上限，或 min=1 且 max 不设） | 20 | **缺，需新增** |
| E | （显式）敷料包（纸塑袋） | 可并入 B，不进 C/D | 仅 ×0.8 | 同 B | 靠「不进九九九折」保证 |

删除或停用现行「无类型、全局」的两条宽规则，避免与 A–D 双命中。叠乘顺序保持：先 0.8 再 0.999，分步四舍五入到分。

引擎改动（与规则同批）：

- `findScopedDiscountPolicies` / 叠乘循环：对每条 policy 调用 `BillingConditionEvaluator.packTypeMatches(policy, type)`（或 `scope.acceptedTypes`）。
- 单测覆盖下表验收例；改完跑 G1–G3（manifest / keywords / `rules compare`），附一专属条目按规范验收。

### 4.2 导出分科室——配置与排查（先核实再改）

| 项 | 文件 / 位置 | 动作 |
|---|---|---|
| 确认 clerk 布局 | `clerk-rules/baseline/ZYY-D1.json` | **已正确**，一般不必改文案；确认生产 DB 已编译/落库该 baseline |
| 确认模板 mapping | 客户 `export_template.column_mapping` | 应含 `billLayout=dept_split`、`billColumnLayout=fuyi_extended_11col`；缺失则补种子或重跑 clerk→模板同步 |
| 导出运行时 | `ClerkExportLayoutMerger`、`BillExportLayoutResolver.useDeptSplitWorkbook` | 保证医院名解析到 `ZYY-D1` 后强制 dept_split，**不要**在附一行数&gt;1000 时掉回 combined |
| 预览一致性（可选） | `ExportEngineServiceImpl.buildExportProfileFields` | 预览也合并 clerk，避免 UI 与文件不一致 |
| Job 数据 | 对账 Job 行 `sheetName` | 若 `distinctSheetCount≤1`，查导入源是否被合成单表；不是改折扣 JSON |

对照实现：不必抄电力/南岗的 `keepColumns`；附一要的是**多 Sheet**，不是在单表里加器械数列。

### 4.3 验收例子

| 场景 | 期望 |

### 4.4 已在生产 / 还缺（仓库视角）

| 能力 | 仓库 | 生产 |
|---|---|---|
| 八折始终 + 九九九折仅 `billingPieces`&lt;3（无类型） | 已有（`3ef3640b`） | 以部署版本为准；未部署则生产仍可能是永远 ×0.8×0.999 或更早 0.99 |
| 按包类型分支、无纺布&lt;3 固定 13.2、敷料纸塑只八折、低温类件数无关叠 0.999 | **缺** | **缺** |
| clerk `dept_split` + 11 列文案 | 已有 | 若客户导出仍单表，优先查解析/模板/行数&gt;1000 的 auto 合并，而不是再写一条相同 JSON |

## 5. 建议实施顺序

1. 折扣：先给 `BillingPolicyApplier` 接上包类型门控，再按 §4.1 拆/换 `ZYY-D1` billingPolicies，重算 index/manifest。  
2. 导出：对客户反馈的 Job 看 `billLayout`、`distinctSheetCount`、实际 xlsx Sheet 数；缺映射则补模板/clerk 落库，确认 dept_split 在 &gt;1000 行时仍多 Sheet。  
3. 回归：附一 6/7 月样张抽检无纺布额外包与敷料纸塑袋；导出 Sheet 数与原始表科室对齐。
