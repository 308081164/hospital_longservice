# 双层袋识别、特色价不打折、克氏针折算：问题分析

日期：2026-10-14  
范围：高健微信 + 对账页截图 + 当前仓库计价代码与 baseline  
第 1–4 节是改之前的原因。第 5 节是按更正要求已经落地的口径。

对照材料：

- `省二院松北9月10月.xlsx`，黑龙江省第二医院（松北院区）
- `省医院多科9月.xlsx`，黑龙江省医院（南岗院区）
- 特色规则：`billing-rules/baseline/ERYY-SB.json`、`SHENG-YY-NG.json`、`SHENG-YY-XF.json`
- 内勤折扣：松北「标准价七折」0.7；南岗、香坊「标准价六折」0.6
- 双层袋几何标记：`PricingEngine.DOUBLE_BAG_MARK`
- 特色规则关键词：`双@contains`
- 小件折算：通用 `needle`，克氏针，不超过 5 件按 1 件
- 生产版本：2026-10-13 部署的 `497114d0`，规则基线 `d60b536f`

---

## 1. 结论

三件事不是同一个故障。

**1. 「双」和「/双」现在被当成一回事。** 特色规则关键词是 `双@contains`，包名里出现「双」就会进双层袋规则。`双头挖勺` 因此被当成双层袋。引擎里另有一套几何标记，只认 `/双`、`/(双)`、`/（双）`，但选规则时不用它。

**2. 生产环境是昨天的版本，折扣没有漏部署。** 昨天只把松北三条按件规则的 `skipDiscount` 改成 false。南岗、香坊的特色规则仍然是 `skipDiscount: true`，编排器看到这个标记就不乘六折。松北截图里的克氏针已经有「导出阶段折扣：标准价七折」；南岗截图里的手术包和双头挖勺没有这一步。高健说的「另外两家」，和规则对得上的是省医院南岗、香坊。

**3. 克氏针没有把双层袋价和小件折算叠乘。** 特色规则先命中，小件「5 件折 1 件」被整段跳过。系统按器械数列的 2 件计价，账单对得上「先折成 1 件，再加两只列出的袋，再七折」。

## 2. 双层袋必须是「/双」

### 2.1 现在怎么匹配

松北、南岗、香坊的双层袋规则关键词都是 `双@contains`，规则级匹配模式也是 `contains`。`@contains` 是子串包含：文本里有「双」就命中，不要求斜杠，也不要求左右是词边界。

因此这些包名都会进同一条规则：

| 包名 | 有没有 `/双` | 当前会不会进双层袋规则 |
|---|---|---|
| `克氏针1.2-1/双Z7530` | 有 | 会 |
| `克氏针1/双/Z2090` | 有 | 类型还要是额外包（纸塑袋）才行，见 2.3 |
| `双头挖勺-1/Z7526` | 没有，是器械名 | 会 |
| `单极电凝3#(双)` | 没有斜杠 | 按关键词会 |
| `肺瓣钳把…(双层)` | 没有斜杠 | 按关键词会 |

南岗截图已经坐实了误命中。`双头挖勺-1/Z7526` 的流程写的是「省医院南岗双<3按件5.5加列出的袋」，规则编号 1814，单包计费件数 1，再加一只 10cm 袋 2.50，规则单价 8.00。包名里的「双」来自「双头」，不是双层袋标记。

高健的原话是：之前确认过 `/双` 才代表双层袋，这个包是名字带双。

引擎自己区分过这两种写法。袋尺寸用的标记是：

```29:30:backend/src/main/java/com/hospital/backend/service/PricingEngine.java
    private static final java.util.regex.Pattern DOUBLE_BAG_MARK =
            java.util.regex.Pattern.compile("/[(（]?双[)）]?");
```

它只认 `/双`、`/(双)`、`/（双）`。`双头`、`双层`、`(双)` 对不上。选哪条特色规则时不走这个正则，走的是 `双@contains`。所以几何上不当成双层袋的名字，仍会套上双层袋的按件价。

### 2.2 这个放宽是 2026-10-12 故意做的

10 月 12 日的分析把 Excel「包名称带双」理解成包名里出现「双」即可，并写明 `双保`、`双层`、`/双Z` 都要算。当时松北种子还是关键词 `/双`，对不上 `/双保/`。随后 baseline 改成了现在的 `双@contains`。

今天的客户口径和那次放宽相反：双层袋标记是 `/双`，器械名称里的「双」不算。两套口径不能同时成立。按今天的口径，`双头挖勺` 不应进入规则 1814；按 10 月 12 日的口径，它应该进入。

### 2.3 松北表格里另外两行

`克氏针1/双/Z2090` 是单包装包、低温纸塑 200×600。双层袋规则的类型只收「额外包（纸塑袋）」，这条进不去。低温 20cm 标准价 28 元，再七折是 19.60，和账单一致，差额 0。这里的 `/双` 没有被漏掉成另一套高温公式。

`单极电凝3#(双)` 和 `肺瓣钳把(双层)` 的标签是「标准灭菌」。按现在的 `双@contains`，这两行也应该进特色规则。截图没有打开它们的流程，不能把「显示标准灭菌」写成系统已经按 `/双` 排除了它们。`双头挖勺` 那一行已经证明包含匹配是开着的。

## 3. 特色价不打折：不是生产落后，是昨天只改了松北

### 3.1 生产已经是昨天的版本

2026-10-13 生产提交是 `497114d0`，规则基线 `d60b536f`，核对通过。松北克氏针的流程第 9 步写着「导出阶段折扣：标准价七折，单价 11.20」。这一步是昨天把松北按件规则的 `skipDiscount` 放开之后才有的。如果生产还停在更早的包，这行不会出现七折。

南岗没有这一步，是因为南岗的规则没改，不是因为服务器没更新。

### 3.2 昨天改了什么、没改什么

昨天只把 `ERYY-SB.json` 里三条按件规则改成 `skipDiscount: false`：

- 省二松北双&lt;3按件5.5加列出的袋
- 省二松北双≥3按件5.5仅外层袋
- 省二松北小腔包按件5.5加5元

「钉≥10 固定 50」仍是一口价，`skipDiscount` 仍为 true。

编排器没有改。它仍然是：特色结果带了 `skipHospitalDiscount` 就不调用「标准价×折」。南岗、香坊的特色规则这个标记还在。

南岗 14 条产品规则里 12 条跳过折扣，其中 8 条关键词带「双」。香坊 12 条全部跳过折扣，双层袋两条也在里面。两家内勤都是「标准价六折」，倍率 0.6。

截图算术：

| 行 | 折前 | 应有折扣 | 账单单价 | 系统规则单价 |
|---|---|---|---|---|
| 南岗手术包-6件，6 件 | 6×5.50+3.38=36.38 | ×0.6=21.83 | 21.83 | 36.38，没有折扣步骤 |
| 南岗双头挖勺，1 件 + 10cm 袋 | 5.50+2.50=8.00 | ×0.6=4.80 | 4.80 | 8.00，没有折扣步骤 |
| 松北克氏针 `/双`，系统按 2 件 | 11+5=16.00 | ×0.7=11.20 | 7.35 | 11.20，七折已经打过 |

手术包差额 +14.55 = 36.38−21.83。双头挖勺 3 包差额 +9.60 = (8.00−4.80)×3。这两笔都是少掉的四成，不是公式本身加错。

松北这行的差额不是「没打折」。11.20 已经是 16.00 的七折。和账单差在件数，见第 4 节。

### 3.3 「另外两家」

高健说这家和昨天那家一样没打折，还要看另外两家。昨天那家是松北，今天截图这家里的南岗对得上。和南岗同一套「标准价六折」、双层袋规则仍跳过折扣的另一家是香坊。

下面这些医院的双层袋规则也是 `skipDiscount: true`，但内勤基线里没有「标准价×折」这种导出折扣，不能把南岗的差额直接套过去：奥兰、市红十字、森海、远东心内、电机厂。

## 4. 克氏针：双层袋和小件折算没有叠乘

包名 `克氏针1.2-1/双Z7530`，类型额外包（纸塑袋），材料「高温纸塑袋75×200，高温纸塑袋100×350」，器械数 2，包数 1。账单单价 7.35，规则单价 11.20。

### 4.1 系统实际走的路径

流程写的是：

1. 产品识别到克氏针，类别小件，计价路径标成标准，并注明未作为计价路径。
2. 命中「省二松北双&lt;3按件5.5加列出的袋」，规则 1809。
3. 按每件 5.50 元，单包计费件数 **2**，单价 11.00。
4. 两只列出的袋都加：外层 10cm 计 2.50，内层 7.5cm 计 2.50，合计 5.00。
5. 七折：16.00×0.7=**11.20**。

`1.2` 是针的号数，带小数，不计件数。`-1` 是包名里的件数，但计价用的是器械数列，不是包名件数：

```171:172:backend/src/main/java/com/hospital/backend/service/PricingEngine.java
 // 计价始终使用Excel器械数（effectiveCount），不从包名覆盖。
 // 包名解析数量仅用于字段一致性核对（BillRowFieldConsistencyValidator），不影响计价。
```

器械数 2、包数 1，所以计费件数是 2。75mm、100mm 都落到 10cm 档 2.50 元。两只袋 5.00 元。11+5=16，再七折得 11.20。和流程一致。

### 4.2 小件折算为什么没参加

通用小件规则：关键词含克氏针，不超过 5 件按 1 件，超过 5 件按每 5 件进一。

这段只在特色规则没有先命中时才跑。特色价先匹配成功后，折算被跳过：

```212:232:backend/src/main/java/com/hospital/backend/service/PricingEngine.java
        SpecialPriceResult preMatchedSpecialPrice = zeroPriceOverride != null
                ? zeroPriceOverride
                : findSpecialFixedPrice(
                        row, bagSize, effectiveCount, matchedProductId, matchedVariantId, false, 0, 0);
        // ...
        if (preMatchedSpecialPrice == null && !isZsdInstrumentPack) {
            int countBeforeSpecialFold = effectiveCount;
            FoldApplyResult foldResult = applySpecialFoldRules(row, bagSize, effectiveCount, notes);
            effectiveCount = foldResult.effectiveCount();
```

后面的通用克氏针折算同样要求 `preMatchedSpecialPrice == null`。

所以不是两条价叠在一起。是双层袋规则用折算前的 2 件抢走了计价，克氏针的「5 件折 1 件」没有执行。界面上的「未作为计价路径」就是这件事：产品库认出了克氏针，件数没有按小件折。

高健说「该是道外五件一样的，却按那两件算的」。道外没有单独的克氏针特色规则，用的就是这套通用折算：不超过 5 件算 1 件。这行器械数 2，若先折算，计费件数是 1，不是 2。

### 4.3 账单 7.35 怎么还原

7.35÷0.7=10.50。10.50=5.50×1+2.50+2.50。

也就是：计费件数 1，两只列出的袋都加，再七折。这和「先把 2 件克氏针折成 1 件，再走 &lt;3 的加袋公式，再七折」是同一个数。

| 步骤 | 系统现在 | 和账单一致的折法 |
|---|---|---|
| 件数 | 器械数 2，不折算 | 2≤5，按克氏针折成 1 |
| 件费 | 11.00 | 5.50 |
| 两只袋 | 5.00 | 5.00 |
| 折前 | 16.00 | 10.50 |
| 七折 | 11.20 | 7.35 |

七折两边都有。差额 +3.85 是多算的那 1 件（5.50×0.7），不是没打折。

若改成只认 `/双`，这行包名仍有 `/双`，还是会进双层袋规则，小件折算仍会被跳过，11.20 不会自己变成 7.35。件数和标记是两件独立的事。

## 5. 已落地

按当天的更正要求已经改代码，本节是落地口径。上面第 1–4 节仍是改之前的原因。

1. 八家双层袋规则的关键词从 `双@contains` 改为只认 `/双`、`/(双)`、`/（双）`。`双头`、`(双)`、`双层` 不再进双层袋规则。`/双保` 仍会命中，因为 `/双` 是它的子串，和几何标记同一口径。
2. 编排器对特色价和标准价都乘内勤导出折扣，不再看规则上的 `skipDiscount`。内勤一口价（账单价规则命中）不再乘折扣。特色一口价「钉≥10 固定 50」会再乘松北七折，变成 35.00。敷料包仍保留原价。
3. `/双` 规则不再在折算前锁死件数。没有其它特色规则时，先做通用小件折算，再用折算后的件数套双层袋公式。克氏针 2 件折成 1 件后，5.50+2.50+2.50=10.50，再七折是 7.35。其它特色规则先命中时，仍由那条规则定价。
