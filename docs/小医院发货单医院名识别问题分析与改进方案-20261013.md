# 小医院发货单无法识别医院名称：问题分析与改进方案

日期：2026-10-13  
范围：微信反馈截图 + 发货单样例 + 当前前后端医院名识别代码  
2026-10-13 已按第 6 节落地：机构后缀、发货日期列汇总带、未建档提示。下文仍保留当时的原因分析。

- 样例：`HEBDeliveryNoteSummaryWithPackingMeterialWithDiscountSeperateByDPDecimal3Digit (1).xlsx`（微信接收，工作表「中西医科」，15 行）

## 1. 结论

医院名就在 **D9**。这次不是「名称不在 D9」，而是读到了 D9 之后又把它丢掉了。

样例 D9 的原文是 **晟龄中西医结合诊所**。前后端的合法医院名都要求单元格里必须出现「医院」二字。诊所、门诊部、卫生院过不了这道门，于是：

1. 表内名称作废。
2. 页面退回英文文件名 `HEBDeliveryNoteSummaryWithPackingMeterial...`。
3. 科室仍是工作表名「中西医科」，4 行明细、原总价 213.50 都正常。
4. 因为没有医院名，匹配不到客户档案，计价走通用「标准灭菌」。截图里「无需修改」只说明单价和标准价一致，不说明医院已经认出来了。

「有几个小医院」会一起中招：凡是机构名不以「医院」结尾、或名称里没有「医院」的，现有 D8/D9 规则都会拒绝。

## 3. 代码为什么拒绝 D9

前端和后端是同一条规则，两边都要改，只改一边页面仍会对不上。

前端 `isValidHospitalName`：

```47:54:frontend/src/utils/reconciliationHospitalName.ts
/** 铂康标准账单 D8/D9 医院名校验：必须含「医院」，拒绝日期/数字/表头字段/科室名。 */
export function isValidHospitalName(name?: string | null): boolean {
  const trimmed = (name ?? '').trim()
  if (!trimmed || !trimmed.includes('医院')) return false
  if (isLikelyDepartmentName(trimmed) || isDateRangeText(trimmed)) return false
  ...
}
```

D8/D9 只接受通过上面这个函数的文本，D9 优先：

```67:76:frontend/src/utils/reconciliationHospitalName.ts
export function resolveHospitalNameFromColumnD(
  matrix: unknown[][],
  _headerRowIndex?: number
): string {
  const d9 = readColumnDCell(matrix, EXCEL_D9_ROW_INDEX)
  if (isValidHospitalName(d9)) return d9
  const d8 = readColumnDCell(matrix, EXCEL_D8_ROW_INDEX)
  if (isValidHospitalName(d8)) return d8
  return ''
}
```

后端 `ExcelBillImportSupport.isLikelyHospitalDisplayName` 和 `ReconciliationHospitalNameResolver.isLikelyHospitalName` 同样要求 `contains("医院")`。

对这个文件的判定：

| 候选 | 单元格 | 结果 |
|---|---|---|
| D9 | 晟龄中西医结合诊所 | 读到了，因为没有「医院」被拒绝 |
| D8 | 发货日期 | 表头，拒绝 |
| A 列汇总行 | A9 为空（名称在 D 列） | 后备路径也是空 |
| 表头区文本 | 只扫描表头行及其上方 | 诊所名在表头下一行，扫不到 |
| 文件名 | 英文报表名，不含「账单/发货单」等中文后缀 | 去不掉，整串被当成医院名显示 |

所以对话里「统一读 D9，可能名称不在这个单元格」只说对了一半：位置就是 D9，被拒绝的是后缀。

同一份前端文件里，判断「是不是科室」时已经承认诊所是机构后缀：

```5:5:frontend/src/utils/reconciliationHospitalName.ts
const HOSPITAL_NAME_PATTERN = /(医院|诊所|集团|中心|卫生院|卫生服务中心|医疗美容|妇产医院|肛肠医院)$/
```

这条正则只用来避免把「某某诊所」误当成短科室名。真正收医院名的函数没有用它，仍然只认「医院」。

## 4. 页面上为什么看起来像「没读到医院」

识别失败后的回退顺序是：表内合法医院名 → 文件名推断 → 原样文件名。

`resolveReconciliationHospitalName` 在表内名称不合法时，会返回文件名去掉扩展名后的字符串。这个英文文件名不含中文「发货单」「账单」，后缀替换不会生效，徽章就显示整段文件名。截图顶部那条长文件名就是这个回退，不是用户又传错了文件。

科室没有丢，是因为明细的科室来自 **工作表名**「中西医科」，不是来自医院名。第 11 行的「中西医科」只是科室汇总，没有发货日期和包名，不会变成明细。

计价显示「标准灭菌 / 高温纸塑袋25cm计费 / 无需修改」，是因为医院名已经变成英文文件名，客户解析对不上任何一家。引擎用通用标准价。镊子缸 2 件、250×300 纸塑袋，标准价 16.50，和原单价相同，所以状态是无需修改。这不能当成「这家诊所的规则已经生效」。

行详情里没有单独的医院字段。医院名只出现在文件条徽章上。详情看起来完整，不代表医院已识别。

## 5. 为什么小医院更容易中招

铂康「发货单汇总表-显示包装材料」有两种常见摆法，代码只把第一种里「带医院二字」的名字当成成功。

**摆法 A：大医院标准账单。** 医院全称写在固定单元格 D8 或 D9，和「发货日期」列不是同一列。现有单测覆盖的就是这种，例如 D8「哈尔滨冰城医疗美容医院」、D9「呼兰中医院」。这些名字都含「医院」，所以一直正常。

**摆法 B：这份诊所账单。** 左侧空出 A–C 列，表头从 D 列开始。医院名不是另一列的元数据，而是表头下一行、写在「发货日期」列里的汇总带。因为整张表右移了 3 列，汇总带正好落在 D9。读 D9 能碰到它，但后缀校验把它扔掉。

如果另一家小医院的表没有这 3 列左边距，同一个汇总带会落在 A9 或 B9、C9。现在的后备只扫 **A 列**，而且同样要求含「医院」。左边距不是 0 也不是 3 时，放宽后缀也读不到。

已知还会被同一道门挡住的机构名（仓库里已有客户，但发货单若把全称写在汇总行，一样认不出）：

- 以「诊所」结尾，例如本样例
- 以「门诊部」结尾，例如「哈尔滨道外区松电慢性病专科门诊部」「哈尔滨百年夏氏中医门诊部」
- 以「卫生院」「卫生服务中心」结尾

单独的「门诊部」「中西医科」「手术室」必须继续当科室，不能因为放宽后缀就变成医院名。

## 6. 改进方案

### 6.1 机构名校验改为「后缀」，不再要求必须含「医院」

前后端使用同一套判断：

- 接受：名称中含「医院」，或以「诊所」「门诊部」「卫生院」「卫生服务中心」结尾。
- 仍然拒绝：空值、纯数字、账期行、含「发货单汇总表」、等于「发货日期」、科室名。
- 「门诊部」本身继续是科室。只有更长的「某某门诊部」才算机构。
- 不要把所有以「中心」结尾的都收进来。「内镜中心」「供应中心」「体检中心」是科室。只额外接受「卫生服务中心」。

后端 `isLikelyHospitalDisplayName`、`isLikelyHospitalName` 与前端 `isValidHospitalName` 一起改。汇总行跳过条件 `isHospitalSummaryRow` 目前只认「医院」「中心」，应同时认「诊所」「门诊部」「卫生院」，避免以后汇总行被当成明细或科室。

### 6.2 医院名优先读「表头下一行的发货日期列」，D8/D9 保留给摆法 A

建议顺序：

1. 先按现在的规则读 D8、D9，但用 6.1 的新校验。摆法 A 的大医院行为不变；本样例的 D9 会直接通过。
2. 若 D8/D9 都不是机构名，再从表头行的「发货日期」那一列往下看。遇到没有包名、且文本通过 6.1 的单元格，就用它。这样左边距不是 3 列时也能读到。
3. 现有的 A 列汇总行后备保留，同样改用 6.1。它是第 2 步在「发货日期位于 A 列」时的特例，留着避免旧表回归。
4. 表内一旦有合法机构名，禁止再被英文文件名覆盖。

第 2 步不要扫整列正文。只接受「无发货单号、无类型、无包名」的汇总带，避免把包名里偶然出现的「医院」当成机构名。

### 6.3 认出名字但档案里没有这家客户时，不要再显示文件名

`ReconciliationHospitalNameResolver` 在客户表查不到时，已经会保留表内原名（现有单测 `preservesExcelHospitalNameWhenCustomerNotInRoster`）。6.1 生效后，本样例应显示「晟龄中西医结合诊所」，而不是英文文件名。

此时仍可能没有这家诊所的特殊计价，页面继续走标准灭菌是对的。徽章旁可以加一句「未匹配到客户档案」，方便内勤去建档或加别名。这一句是提示，不改单价。

### 6.4 明确不改的部分

- 不把工作表名「中西医科」提升为医院名。
- 不从文件名猜测诊所。这个文件名里没有中文机构名。
- 不改标准灭菌、纸塑袋阶梯和这 4 行的单价。它们在医院未建档时本来就该走标准价。
- 不把 D 列写死成「永远是医院名列」。摆法 A 里 D 列是元数据列，摆法 B 里 D 列碰巧是发货日期列。6.2 用表头找发货日期列，避免再靠左边距碰运气。
