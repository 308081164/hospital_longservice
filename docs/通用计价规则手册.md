## 第 1 章 · 总则

### 1.1 适用范围

「通用计价」= 任何医院账单行都会走的**默认计价逻辑全集**，即未命中客户特色规则（固定价 / 折算 / 倍率 / 加收）时的标准灭菌计价路径，外加所有医院共用的件数折算、包装费、折扣、校验告警机制。

- 计价模式 `pricingMode` 已在编译期**统一锁定为 `hybrid`**：`special_only` 与 `standard` 模式已停用（`PricingRuleCompiler.java:94-99`，日志「已锁定为 hybrid」）；未解析到客户时同样默认 `hybrid`（`PricingRuleCompiler.java:62-67`）。
- 引擎内仍保留 `special_only 未命中特色规则→保留原价` 分支（`PricingEngine.java:336-348`），属遗留防御，正常不会再进入。
- 客户可通过 `standardPricingOverride` **深合并**覆盖标准价表数值（高温/低温/敷料包三节），公式不变、仅换价目（`PricingRuleCompiler.java:368-404`；示例：中医附一独立价表 `backend/src/main/resources/billing-seeds/phase-zyy-d1-standard-pricing-20260723.json`）。本手册第 4 章 / 附录 A 给出的是**全局默认价**。

### 1.4 计价分支优先级（高 → 低）

| 优先级 | 分支 | 说明 |
|---|---|---|
| 1 | 0 元覆盖 / 特色固定价 FIXED_PRICE（含通用**软镜 300**） | 命中即定价，pricingPath=`fixed` |
| 2 | 产品主数据公开价格（结构化匹配，特性开关，默认关闭） | `PricingEngine.java:1025-1050` |
| 3 | FOLD 折算规则（通用小件 5 合 1 / 院级折算） | 只折算件数；价格仍走标准路径或规则自带 unitPrice |

| 5 | 未识别包装类型 → 保留原价 + 人工复核 | pricingPath=`null` |

## 第 2 章 · 包类型识别

### GEN-01 · 包材类别判定（包材优先于类型标签）

**出处**：`PackPricingCategoryResolver.java:37-51`；引擎侧二次确认 `PricingEngine.java:156-168`。

| 判定顺序 | 条件 | 结论 |
|---|---|---|
| 1 | 包材含「无纺布」且不含「纸塑袋」 | 无纺布 |
| 2 | 包材含「纸塑袋」/「低温灭菌」/「双层袋」 | 纸塑袋 |
| 3 | 类型含「无纺布」且不含「纸塑袋」 | 无纺布 |
| 4 | 类型含「纸塑袋」/「低温灭菌」 | 纸塑袋 |
| 5 | 都不满足 | UNKNOWN（保留原价 + 复核，GEN-24） |

> 要点：**包装材料列优先于类型列**。账单类型误标「纸塑袋」但包材为无纺布时，仍走无纺布计价（`PricingEngine.java:161-168`）。

### GEN-02 · 包分类（5 类）

**出处**：`PackPricingCategoryResolver.java:19-35, 53-77`；枚举 `PackPricingCategory.java:6-17`。

| 分类 | 含义 | 进入条件 |
|---|---|---|
| `DRESSING_PAPER` | 敷料包(纸塑袋) | 类型含「敷料包」+「纸塑袋」；或棉球类纸塑行（包名含「棉球」且不含「棉球缸」，类型含「纸塑袋」，且为敷料包型或单包件数 ≤0） |
| `DRESSING_NONWOVEN` | 敷料包(无纺布) | 无纺布基底 + 类型含「敷料包」，或包名含「驱血带」且为敷料类 |
| `INSTRUMENT_PAPER` | 器械/额外包(纸塑袋) | 纸塑基底的其他行；**纸塑袋驱血带归此类**（按纸塑额外包计价，不走 W 码分档，`:63-67`） |
| `INSTRUMENT_NONWOVEN` | 器械/额外包(无纺布) | 无纺布基底的其他行 |
| `UNKNOWN` | 未识别 | 保留原价 + 复核 |

### GEN-03 · 器械包(ZSD) 包材推断为无纺布

**出处**：`PricingEngine.java:2454-2466`（调用点 `:98`）；ZSD 类型判定 `:2540-2547`。

源账单「器械包(ZSD)」常无包装材料列：包材为空且类型含「器械包(ZSD)」（或「器械包」+「ZSD」）时，按铂康惯例**补全为「无纺布」**，走高温无纺布标准阶梯，并记 note「器械包(ZSD)未填写包装材料，按高温无纺布标准阶梯计费。」

> 附一（capMode=fuyi）另有睿思 export 包材编码归一化（`PricingEngine.java:2472-2538`），属客户级适配，不影响通用规则。

### GEN-04 · 低温判定

**出处**：`PricingEngine.java:176-178`。

`type + packName + packageMaterial` 含「低温」，或类型含「ETO」/「EO」，或包材含「低温灭菌」→ 低温行。`pathOverride.disableLowTemp=true` 时强制按高温（客户级路径覆盖，默认 false）。

### GEN-05 · 双层袋标记与第二袋尺寸

**出处**：标记正则 `PricingEngine.java:29-30`；判定 `:179-181`；第二袋尺寸提取 `:1562-1591`。

- 包名含 `/双`、`/(双)`、`/（双）`（后接可选右括号），或包材含「双层袋」→ 双层袋。
- 第二袋尺寸：从「双」标记后提取两位数字（`/双15`→15，`/(双)Z1526`→15）；**特殊映射 75→10**（`:1577-1578`）；「双」后紧跟汉字 → 不追加第二袋费（`:1570-1571`）。

### GEN-06 · 袋尺寸检测

**出处**：`PricingEngine.java:1512-1559`（主流程）、`:1593-1608`（Z 码）、`:1610-1637`（袋型配置与关键词表）。

对「包材 + 包名」文本按以下顺序识别袋宽（cm），结果缓存（上限 2000 条，`:1553-1556`）：

| 顺序 | 规则 | 示例 |
|---|---|---|
| 1 | `数字×数字` 且首数 ≥50（视为 mm）→ 首数 ÷10，精确匹配袋型表；无精确则取不小于它的最小袋型；再大则取最大袋型 | `200×440` → 20cm |
| 2 | 袋型关键词表命中（高温/低温袋型配置的 keywords 合集） | 「15cm」「中」→ 15 |
| 3 | 大写 `Z` 后两位数字 | `Z1530` → 15 |

默认袋型表见附录 A。识别失败返回 0，后续按各分支的「未识别规格」逻辑处理。

## 第 3 章 · 计费件数确定

### GEN-07 · Excel 器械数优先（包名解析不参与计价）

**出处**：`PricingEngine.java:150-151`（代码内注释即规则）。

> **计价始终使用 Excel 器械数列（instrumentCount），不从包名覆盖。包名解析数量仅用于字段一致性核对（`BillRowFieldConsistencyValidator`），不影响计价金额。**

`PackNameSpecParser.extractTotalPieceCountFromPackName`（`PackNameSpecParser.java:148-167`）的包名件数解析（`-N` 累加 → `N件` → 多段「名+数」累加 → 末尾数字 → 容器 盒/筐/盘 加计；针架、手机/型号编码类跳过）只服务两类用途：
1. 字段一致性 amber 核对（GEN-44 的 `INSTRUMENT_COUNT_MISMATCH`）；
2. 产品主数据导入的规格指纹（`PackNameSpecParser.java:65-94`）。

### GEN-08 · 多包件数均分（packCount > 1）

**出处**：`PricingEngine.java:123-134, 169-174`。

- `effectiveCount = round(instrumentCount / packCount)`，非敷料行至少抬到 1（`:125-131`）。
- 器械包(ZSD) 多包时，材料计费件数取**单包件数** `perPackInstrumentCount = max(1, round(instrumentCount / packCount))`（`:132-134, 314-316`），即 ZSD 按单包器械总数走阶梯。

### GEN-09 · 敷料按包行（0 件不抬 1）

**出处**：`PricingEngine.java:1435-1453`（判定）、`:123-131`（应用）。

器械数为 0 的敷料类行（棉球纸塑敷料、敷料包(纸塑袋)、无纺布驱血带；棉球缸除外）允许 effectiveCount=0，**不强制抬为 1 件**，按包计价。

## 第 4 章 · 标准计价公式（分包类型）

> 入口：`PricingEngine.java:356-544` 的 `switch (packCategory)`。以下价格均为 `DefaultPricingTemplate` 全局默认；客户 `standardPricingOverride` 可换数值（1.1 节）。

### 4.1 高温纸塑袋（INSTRUMENT_PAPER + 非低温）

**出处**：`computeHighTempPaperPlastic`，`PricingEngine.java:1643-1719`。

**GEN-13 袋尺寸上限**：袋宽 >25cm 一律按 25cm 计费并记 note（`:1644-1649`）。未识别袋型 → 返回 null → 行状态 `skipped`（人工核定）。

**GEN-10 · <3 件：件费 + 袋费，封顶 16.5**（capMode=standard 默认，`:1690-1718`）

```
单价 = min( 5.5 × 件数 + 袋费1 (+ 双袋费2), 16.5 )
```

| 袋宽 | 10cm | 15cm | 20cm | 25cm |
|---|---|---|---|---|
| 袋费 | 2.5 | 5.5 | 7.5 | 10.5 |

> 注意：`minCharge=16.5` 在代码中是 **`Math.min` 封顶**（最高收费），不是最低消费。例：1 件 15cm → 5.5+5.5=**11 元**；2 件 25cm → 11+10.5=21.5 → 压到 **16.5 元**。

**GEN-11 · ≥3 件：按件计费，免袋费**（`:1696-1711`）

```
单价 = 5.5 × 件数        （不再计袋费）
```

**GEN-12 · 双层袋第二层袋费**（`:1660-1668, 1697-1704`）

- <3 件：加第二袋费（按 GEN-05 提取的 Z 尺寸查袋价，>25 按 25）。
- ≥3 件：默认免收全部袋费；仅当院级配置 `chargeDoubleBagWhenCapped=true` 时，仍追加第二袋费。

**capMode 变体**（客户级配置，`:1671-1694`）：

| capMode | 行为 |

## 第 5 章 · 针类 / 小件折算体系

### GEN-26 · 折算总顺序

### GEN-27 / GEN-28 · 通用小件 5 合 1（默认模板内置 FOLD 规则）

默认模板自带两条全局 FOLD 规则，关键词均为 8 个小件词：**克氏针、银质针、内热针、车针、拔髓针、扩大针、根扩针、卷棉子**；触发件数 5、折算比例 5（即 5 件算 1 件）、折算后单价 5.5 元/件：

| 规则名 | priority | 件数条件 | skipPackaging | 价格行为 |
|---|---|---|---|---|
| 通用小件5合1含包材 | 50 | ≤10 件（maxInstrumentCount=10） | 否 | 5.5 × 折算件数 **+ 标准包材费**（袋宽 <20cm→2.5，≥20cm→4.0），`:472-477` |
| 通用小件5合1免包材 | 51 | ≥11 件（minInstrumentCount=11） | 是 | 5.5 × 折算件数，不加袋费，`:478-490` |

折算件数 = `ceil(件数 / 5)`（`foldCount`，`:1401-1404`）。命中后规则名直接作为 pricingRule 展示名（`:546-548`）。

### GEN-29 · FOLD extraCount（盒 1 固定加计）

**出处**：`PricingEngine.java:941-951`。

规则带 `extraCount>0` 且器械总数 > extraCount 时，仅对「总数 − extraCount」做折算，盒等容器以 extraCount 固定追加：

```
计费件数 = ceil((器械总数 − extraCount) / foldRatio) + extraCount
```

例：针 5 盒 1（总数 6，extraCount=1）→ ceil(5/5) + 1 = **2 件**。extraCount 规则按 5.5/件计件费，含包材时叠加标准包材费（`:478-490`；注释明确不走高温纸塑阶梯，避免免包材重复计袋费）。

### GEN-30 · 包名「针N」拆分

**出处**：`PricingEngine.java:228-279`。

包名含「针+数字」（如 `针5`）时：

```
计费件数 = 非针器械数 + ceil(针数 N / 折算比例)
```

- 非针器械数：包名中全部「器械名+数字」段求和（`sumAllNumbers`，`:2336-2344`；如 `剪刀2止血钳1探针1`→3）；无数字段时退回末位数字，再退回 `max(1, effectiveCount − N)`。
- 「针N」后还有其他器械段（如 `针5钢丝4`）时，后段数字一并计入非针器械数（`:265-267`）。
- 折算比例：命中带独立配置的小件关键词时用该词配置，否则全局 5（GEN-32）。
- 若「针」是小件关键词的一部分（如「克氏针」）且针后无其他器械 → 不拆分，交给 GEN-31（`:248-252`）。

### GEN-31 · 小件关键词折算（全局兜底）

**出处**：`PricingEngine.java:280-312`。

包名命中 needle 有效关键词时：

| 情形 | 计费件数 |
|---|---|
| 关键词前后均有数字（大小件混合包） | 大件按实 + 小件折算（小件 ≤ 触发件数 → 1 件；否则 ceil(小件数/比例)） |
| 单包总数 ≤ 触发件数（默认 5） | **1 件** |
| 单包总数 > 触发件数 | **ceil(总数 / 5)** |

### GEN-32 · 小件关键词独立配置（keywordConfigs）

**出处**：合并逻辑 `PricingEngine.java:2164-2244`；落库 `HospitalPricingRuleServiceImpl.java:266-321`；请求结构 `BatchNeedleKeywordsRequest.java:8-42`；校验 `RuleSchemaValidator.java:69-77, 168-178`。

needle 节支持**逐关键词独立配置**，覆盖全局默认：

```json
"needle": {
  "threshold": 5, "foldRatio": 5, "keywordMatchMode": "exact_token",
  "keywords": ["克氏针", "车针", "..."],
  "keywordConfigs": [
    { "keyword": "车针", "matchMode": "contains", "threshold": 5, "foldRatio": 5 }
  ]
}
```

| 字段 | 含义 | 缺省 |
|---|---|---|
| `keyword` | 关键词（必填，不重复） | — |
| `matchMode` | 词级匹配模式：contains / exact / exact_token | 沿用全局 keywordMatchMode |
| `threshold` | 触发件数 | 全局 threshold（默认 5） |
| `foldRatio` | 折算比例 | 全局 foldRatio（默认 5） |

有效关键词 = keywordConfigs 配置词（matchMode 转为 `@contains`/`@exact` 后缀）∪ 普通 keywords 中未被覆盖的词（`:2172-2201`）。存储位置：该院 `hospital_pricing_rule.rules_json` 的 needle 节。

### GEN-33 · 关键词匹配模式

**出处**：`BillingConditionEvaluator.java:18-21, 54-57, 128-149`；FOLD 门控默认 `PricingEngine.java:932-935`。

| 模式 | 行为 |
|---|---|
| `exact_token`（小件/FOLD 默认） | 关键词须作为独立 token 出现（串首/串尾或两侧为非中文字符），仅对**包名**判定；防「针」误伤「车针排」类 |

| 词级后缀 | `词@contains`、`词@exact`（或 `@exact_token`）可逐词覆盖默认模式 |

| `INSTRUMENT_COUNT_MISMATCH` | 包名件数合计 × 包数 ≠ 器械数列 | 包名可解析件数时比对（`:68-89`）；仅斜杠码无件数标注的包名默认单包 1 件（`PackNameSpecParser.java:172-191`） |

豁免（`:126-143`）：针架复合（`针架\d+针\d+`）、手机/型号编码类包名跳过件数核对；器械数为 0 且名称含 敷料/弯盘/棉球/尾纱/洗手服/刷手服/床单/敷布 的行不做件数核对。

### GEN-45 · 字段核对错误（error 级，红色感叹号）

**出处**：`BillRowBillingValidator.java:23-54`；note 前缀「【字段核对错误】」。

| 代码 | 含义 |
|---|---|
| `BLANK_PACKAGE_MATERIAL` | 包装材料为空 |
| `ZERO_INSTRUMENT_COUNT` | 器械数为 0 |

- **敷料包类型豁免**：类型含「敷料包」的行不校验（`:51-54`）。
- 产出 `billing_validation` 结构（severity=error），前端按红色高亮（红色感叹号），与 amber 一致性核对互补（`:8-12` 注释）。

### GEN-46 · 校验强制 warning

**出处**：`PricingEngine.java:688-693`。任一校验存在违规 → 行状态强制 `warning`（即使金额无差异），提示人工核对账单列。

## 第 9 章 · 结果状态、总价与 pricingPath

### GEN-47 · 总价重算

**出处**：`PricingEngine.java:624-630`。`cleaning.recomputeTotalsWhenPriceChanges`（默认 true）：**校正总价 = 规则单价 × 包数**；差异 = 校正总价 − 原始总价。配置为 false 时保留原总价并记提示 note（`:637-639`）。

### GEN-48 · 状态判定与 0.05 展示容差

**出处**：`PricingEngine.java:642-693`；容差常量 `:27`。

| 状态 | 条件 |
|---|---|
| `skipped` | 规则无法计算价格（如袋型未识别返回 null） |
| `unchanged` | 无差异；或多报价命中；或**标准路径下**账单单价与规则价相差 ≤ **0.05 元**（展示精度视为一致，`:672-681`，仅未命中固定价时适用） |
| `warning` | 有差额（待人工复核，「一键修正」后变 corrected）；或 requiresReview；或 0 元导入未定价；或被字段校验强制 |
| `corrected` | 前端「一键修正」后设置（非引擎产出） |

### GEN-49 · pricingPath 取值

**出处**：`PricingEngine.java:703, 753-778`；字段注释 `:2365-2366`。

| 取值 | 含义 | 判定 |
|---|---|---|
| `fixed` | 客户校正/固定价路径 | 命中固定价（含软镜 300、0 元覆盖、产品公开价） |
| `standard` | 标准灭菌阶梯路径 | pricingRule 文本含 高温/低温/敷料/路径覆盖/阶梯/纸塑/无纺布/产品主数据公开价格 |
| `preserve` | 保留原价 | `special_only` 未命中特色规则（遗留防御，正常不再出现） |
| `null` | 未归类 | 如「未识别包装类型，保留原价」 |

### GEN-50 · 0 元导入未定价告警

**出处**：`PricingEngine.java:682-683, 2434-2449`。账单 0 元且规则侧也算出 0（未命中 0 元覆盖/固定价）→ 状态 warning，不因差额为 0 误判 unchanged。
