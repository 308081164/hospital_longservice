## 四、根因分析（代码 / 流程）

### 4.1 baseline 单源化后，历史增量种子不再生效

| 位置 | 现象 |
|------|------|
| `BillingSeedMigrationRunner.java:41-42` | `INCREMENTAL_SEEDS = List.of()` — **2026-09 起冻结为空** |
| `BillingRulesBaselineSyncRunner.java` | 启动时仅 `baseline_hash` 驱动 `BaselineRuleSyncService.importAllBaselines()` |
| `scripts/baseline_to_manifest.py` | manifest **只**从 `baseline/*.json` 生成，过滤 STRICT_KEEP_CODES |

**影响**：`phase-special-charge-17-sync-20260830.json` 中 XINFA 镜头/棉球、`phase-xinfa-lens-cotton-close` 等 **从未写入 baseline 或非 Excel 部分被后续删除**；新部署只 sync baseline 内容。

### 4.2 2026-09-08～17 校正价全面废止 + Excel(4) 权威对齐

| 提交 | 变更 |
|------|------|
| `cee5ce2f` | 删除全部「校正价*」规则 |
| `8523e8ca` | 删除 HULAN-RM 9 条 PDF OCR FIXED_PRICE |
| `eac5496a` | 以用户指定 `特殊收费(4)` 为唯一权威，再删 19 条（含 ZUYAN-SF 针线包/export 探针） |

**影响**：迁移前 manifest 中 HULAN 11 条 / XINFA 9 条 / ZUYAN 9 条 → 现 baseline 仅保留 Excel 段落，**用户若仍期望 PDF/镜头/校正价规则，会感知为「未落库」**。

### 4.3 baseline 生成器 / manifest 不会「丢 Excel 行」

对本案三家，G4 级脚本核查 **PASS**；不存在 `baseline_to_manifest.py` 丢弃、医院未进 index、或 `billingEnabled:false` 导致 Excel 规则缺失的情况：

- `index.json`：三家 `billingEnabled: true`，ruleCount 与 baseline 一致
- `billing-rules-manifest.json`：与 baseline 逐字节同步（`baseline_to_manifest.py --check` 口径）

### 4.4 v17 首录时 manifest 曾滞后（已解决）

`billing_rules_parity_excel17_20260831.md` 曾报「manifest 未覆盖 v17 四院」——**2026-08-31 已修复**；当前 baseline/manifest 已含 v17 Excel 规则。本案缺口 **不是** 首录遗漏，而是 **后续有意删除非 Excel 规则**。

### 4.5 G4 审计范围的误导

`测试用例/excel-manifest-parity-audit-20260902.md` 对 v17 四院均标 **PASS**，但报告口径为「manifest 中 Excel 之外的规则不列差异、不建议删除」。2026-09-17 用户决策改为 **仅 `(4)` 为权威** 后，这些「Extra」规则被删——**G4 历史 PASS ≠ 当前仍保留 PDF/校正价**。

### 4.6 客户编码 / 解析：无问题

`scripts/import_special_pricing_v17.py` + `EXTRA_HOSPITAL_TO_CODE` 正确映射三家中文全称；合并单元格解析与 `phase-special-charge-17-sync` 一致。
