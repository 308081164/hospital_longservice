# S5 纠错测试 — 最小用例集（全局）

> 版本：**2026-07-23** · 对应引擎入口 `PricingEngine.processRow` · 对账行字段与 reconciliation warning TSV 列对齐

## 目的

在 S4「正确账单 pass」基线之上，**故意构造**三类配置/导入错误，验证：

1. 行级 **`status`**（`warning` / `unchanged` / `corrected` / `skipped`）
2. **`notes`** / **`pricingRule`** / **`difference`** / **`expectedUnitPrice`**
3. UI 侧「异常明细 → 人工修正 / 一键修正」链路（**本集单测只覆盖引擎；Job/UI 见各院 `纠错测试记录.md` 的 UI 列**）

## 行输入字段（PricingEngine / 对账导入）

| 字段 | 说明 | 纠错场景常用改法 |
|------|------|------------------|
| `hospitalName` | 医院显示名（规则 hospital 列表匹配） | 一般不改 |
| `type` | 包类型，如 `额外包(纸塑袋)`、`敷料包` | EC-PACK：改错类型 |
| `packName` | 器械/包名 | EC-PACK：去掉规格、改关键字 |
| `packageMaterial` | 袋型/无纺布规格 | EC-PACK：留空或错规格 |
| `instrumentCount` | 件数 | 可选：改数量测 fold |
| `packCount` | 包数 | 可选 |
| `unitPrice` / `totalPrice` | 账单价 | EC-PRICE：+10% 或与引擎期望不一致 |

## 对账结果字段（ProcessedResult → warning 导出）

| 字段 | 含义 |
|------|------|
| `status` | `warning` = 需人工复核；`unchanged` = 与期望一致或 billing 关闭保留原价 |
| `expectedUnitPrice` | 规则引擎期望单价 |
| `correctedTotalPrice` | 校正后总价 |
| `difference` | 账单与期望差额 |
| `pricingRule` | 命中规则简述 |
| `notes` | 人类可读说明（UI 异常明细） |

## 三类标准场景（各院至少跑 1 遍）

### EC-PRICE — 错误单价（+10% 或与规则期望不符）

| 项 | 内容 |
|----|------|
| **操作** | 在 S4 已通过行上，将 `unitPrice`/`totalPrice` 提高约 10%，或填入与固定价/档位不符的价 |
| **期望 status** | `warning` |
| **期望明细** | `difference ≠ 0`；`notes` 含差额或命中规则说明 |
| **代表客户** | DAOWAI-RM（道外）、SHENG-YY-NG（省医院南岗）、ZYY-D1（附一） |
| **自动化** | `PricingEngineS5ErrorCorrectionTest#ecPrice_wrongUnitPrice_yieldsWarning_daowaiLowTempPath` · `PricingEngineTest#pricesHangtianFenghuaSpoonByInstrumentCount` |

### EC-PACK — 错误包名 / 无法识别包材

| 项 | 内容 |
|----|------|
| **操作** | 改 `packName` 使产品规则不匹配；或 `type=敷料包` 且 `packageMaterial` 为空 |
| **期望 status** | `warning`（或 special_only 下回退标准档仍可能 `warning`） |
| **期望明细** | `notes` 含「未能识别」/ 未命中关键字 / 需复核 |
| **代表客户** | HRB-NGJY（九院敷料包 0 元）、NG-FUCHAN（妇产特殊品名） |
| **自动化** | `PricingEngineTest#ngjyZeroDressingPackWithoutMaterialFlagsWarning` · `PricingEngineS5ErrorCorrectionTest#ecPack_unrecognizedDressingPack_yieldsWarning_ngjy` |

### EC-BILLING-OFF — 关闭特色 billing

| 项 | 内容 |
|----|------|
| **操作** | 客户 `billingProfile.enabled=false`（或种子 `billingEnabled: false`）后导入含特色价的行 |
| **期望 status** | `unchanged` |
| **期望明细** | `pricingRule` =「特色账单已关闭」；保留原始 `unitPrice`/`totalPrice` |
| **代表客户** | NG-FUCHAN（历史 special_only/关闭）、任意 P0.1 关闭院 |
| **自动化** | `PricingEngineS5ErrorCorrectionTest#ecBillingOff_keepsOriginalPrice_unchanged` |

## 执行方式

### 自动化（推荐 CI / 本地）

```bash
# 宿主机
cd backend && mvn -q test -Dtest=PricingEngineS5ErrorCorrectionTest,PricingEngineTest#ngjyZeroDressingPackWithoutMaterialFlagsWarning

# Docker（与项目惯例一致）
docker compose -f docker-compose.yml run --rm --no-deps backend mvn -q test -Dtest=PricingEngineS5ErrorCorrectionTest
```

或：

```bash
python3 scripts/s5_error_correction_smoke.py
```

### 手工（每院 3 行）

1. 在 dev 环境打开 S4 对应 **Job #** 同源导入模板  
2. 按上表改 1 行单价、1 行包名、（可选）在客户管理关 billing 再导 1 行  
3. 确认 warning 列表与行状态，点「一键修正」后 status → `corrected`  
4. 结果写入该院 `纠错测试记录.md` 的 **UI/Job** 列

---

## 与 S4 关系

- S4 pass 行作为 **EC-* 改动的黄金行**（包名、件数、期待价不变，只改错字段）  
- 不得用 S4 未覆盖的新品名做 EC-PACK（避免与规则落库纠缠）
