# 针盒针5合1折叠规则修复报告（2026-09-02）

## 用户报告

平房区人民医院 9 月账单：`缝合针(5)` ×58 针被按 0.5 元/针计 29.00 元。
电话确认的期望算法：`[针数/5（进位）＋1（盒）]×5.5` → 58/5=11.5 进位 12，12+1=13，13×5.5=**71.5 元**。
同规则亦存在于黑龙江省妇幼保健院（人口）⑫，一并检查。

## 根因分析（双根因）

### 根因一：生产环境残留手工规则（用户可见的直接原因）

生产 DB 中 PFQ-RM 存在 3 条**从未出现在任何种子/manifest/git 历史**的手工规则：
`平房人民缝合针每把5.5元`（停用）、`平房人民敷料5元`、`平房人民缝合针每针0.5元`（启用）。
启用的 0.5/针规则命中 → 0.5×58=29.00。

残留原因（系统性漏洞）：
1. `BillingRulesManifestReconciler` 仅在 manifest hash **变化**时才执行清理（`syncDeleteNonManifestRules`），
   近期多次部署 manifest 未变 → 清理被跳过 → 手工规则长期残留；
2. CI 生产 parity gate 对 extra（DB 多出）规则仅告警不拦截（`::warning:: ... non-blocking`），
   漂移在部署门禁中不可见。

### 根因二：manifest 规则关键词无法命中真实包名（潜在根因）

即使清掉残留规则，规则仍不会生效：
- 两条规则关键词为单独「针」+ `exact_token` 分词匹配（词边界 = 非 CJK 字符）；
- 平房真实包名 `缝合针(5)` / `缝合针-2件/Z7520` 中「针」前为 CJK「合」→ **不命中**；
- 人口原始账单包名 `全冠套装(7个针)/Z1526` 中「针」前为 CJK「个」→ **不命中**
  （处理后账单的 `全冠套装(针7盒1)` 变体可命中，但系统处理的是原始账单）；
- 结果：行落入全局「通用缝合针按1件含包材」规则 → 8 元（本地 simulate 实测证实）。

### 共性排查

全库扫描 manifest：单独「针」作关键词的规则**仅 4 条**，恰好就是平房、人口两家的「针盒针5合1」规则对。
其他折叠规则（机扩针/洗髓针/荡洗针/棉花针/针类组件等）关键词为具体词组，无此隐患。

## 修复内容

1. **新种子** `phase-special-charge-needle-fold-keyword-fix-20260902.json`（ruleUpdates.setKeywords）：
   - PFQ-RM 两条规则：关键词 `["针"]` → `["针","缝合针"]`
     （命中 缝合针(5)/缝合针-2件；不误伤 车针盒/车针排/持针器/针柄/冲洗针/泪道冲洗针/探针/扩大针排/针盒(有盖)系列——7 月客户处理后账单这些均为标准 8 元/包）
   - HLJ-FY-RK 两条规则：关键词 `["针"]` → `["针","个针"]`
     （「针」继续覆盖 针7盒1 变体；「个针」覆盖 全冠套装(7个针) 变体；不误伤 车针/机扩针/拔髓针/持针器/探针/针柄/冲洗针头）
   - 文件命名须字母序晚于创建规则的 phase-special-charge-12/17/2 种子，否则 manifest 生成器内联补丁会被静默丢弃。
2. **reconciler 彻底化**：`BillingRulesManifestReconciler` 移除 hash 相同即跳过的逻辑，每次启动都全量幂等 reconcile（upsert + 清理非 manifest 规则），杜绝手工漂移持久化。
3. **CI 门禁加固**：`run_prod_parity_gate.sh` 将 extra（DB 多出规则）从非阻塞告警升级为失败，部署时发现漂移即拦截。
4. manifest 重新生成（hash 9ff06dce… → 4477995c…），三处拷贝同步。

## 遗留说明

- Excel ≤6 分支「费用不超过16.5」封顶仅在恰好 6 针时触发（(2+1)×5.5+包材=19>16.5），当前规则模型无封顶字段；引擎袋费路径自带 16.5 封顶（见 13.5 用例 notes「封顶 16.50 元」），实际影响待客户账单出现该边界再行评估。
- 生产环境已处理的历史账单（如 9 月 29.00 元那单）属历史快照，需部署后重新上传/重算才会按新规则出 71.5。
