## 标准逐院验收流程（必须按序）

每家医院（或院区）在 **`测试用例/{规范医院名}/`** 下独立走完全部步骤；上一步未闭环不得跳步（材料缺失见 [`pass_zero与缺材料医院-客户收集清单.txt`](pass_zero与缺材料医院-客户收集清单.txt)）。

| 步 | 名称 | 做什么 | 产出 / 通过标准 | 常用脚本 / 位置 |
|:--:|------|--------|-----------------|-----------------|
| **1** | **材料检查** | 确认存在 **`原始表格/`**、**`处理后表格/`**；同账期成对；铂康简称见 [`铂康材料与医院对照.md`](铂康材料与医院对照.md) | 缺件清单写入该院备注或客户收集清单 | `scripts/ingest_bokang_supplements.py` · 目录扫描 |
| **2** | **表格对比分析** | 原始 vs 处理后逐行对比 | **`数据问题分析.md`** + **`数据问题清单.csv`** | `python3 scripts/analyze_test_case_excel.py --hospital "…"` |
| **3** | **特色规则落库** | 对照 `铂康/特色账单规则.txt`、**特殊价格 PDF/Excel**、[`docs/逐院需求登记表/`](../docs/逐院需求登记表/)；规则写入 **开发环境 DB**（种子 / 客户管理） | `billing-seeds/*.json` 或 UI 配置；重启 backend 后 API/库可查到 | `backend/resources/billing-seeds/` · marker 见 `BillingSeedMigrationRunner` |
| **4** | **系统对账至 pass** | 导入 **原始表格** 批量对账；结合步骤 2 清单与期待价修正规则，迭代直至 **pass** 或 **pass_zero** | `{月}期待价格校正清单.csv` · `{月}系统warning.tsv` · 报告见 [`批量6月系统对账结果.md`](批量6月系统对账结果.md) | `scripts/batch_june_system_test.py` · `batch_june_price_reconciliation.py` |
| **5** | **纠错能力测试** | **故意构造**错误单价/包名/数量等，验证 warning、异常明细、人工修正链路 | 记录用例（可写在院文件夹 `纠错测试记录.md`） | 手工 / 对账 Job API |
| **6** | **需求登记表同步** | 材料或规则变更后更新 **`docs/逐院需求登记表/{医院}.md`**（编码、MAT-15 价格单、结款函折扣等） | md 版本号 + 修订日期 | 与步骤 3 同步 |
| **7** | **导出规则落库** | 结款函独立折扣、账单列裁剪、分科室策略等 **export_template** / 策略配置落库；系统不支持则 **先开发** | `export_template` 或种子；[`SchemaMigrationRunner`](../backend/src/main/java/com/hospital/backend/config/SchemaMigrationRunner.java) 骨架 | 客户管理 · 导出模板 |
| **8** | **导出比对验收** | 导出账单/结款函与 **处理后表格** 字段、金额、折扣行比对 | 签字级 pass（允许已知导出差异在登记表注明） | UI 导出 · Excel diff |

**图例（看板用）：** `⬜` 未开始 · `🔄` 进行中 · `✅` 通过 · `⏭` 跳过（需登记原因） · `🚫` 阻塞（缺材料/缺开发）
