# 气腹针全局针数量拆分误用修复（2026-09-02）

## 用户报告

平房区人民医院 2026-9 月账单（低温灭菌）：

| 包名 | 件数 | 客户价 | 系统行为（修复前） |
|------|------|--------|--------------------|
| 戳卡4转换器1气腹针1 | 6 | 110（正确） | 全局针拆分把「气腹针1」当小件 5 合 1，且非针器械数只取末位数字 → 2 件 → 44 元 |
| 穿刺器5气腹针1 | 6 | 90 | 命中「平房人民针盒针5合1免包材」（旧构建），6 件折为 2 件 → 24 元 |

用户口径：**此医院没有关于「气腹针」的小件计价规则，通用小件计价也没有此规则** —— 气腹针是腹腔镜全价器械，1 件 = 1 件，不参与任何 5 合 1 折算。

## 根因分析

### 根因：全局针数量拆分规则对「针N」模式无差别触发

`PricingEngine.java` 全局针数量规则（`rules.needle`）用正则 `针(\d+)` 扫描包名，**只要包名含「针+数字」就拆分折算**，不区分针的类型：

```java
Matcher needleQtyMatcher = Pattern.compile("针(\\d+)").matcher(packName);
if (... && needleQtyMatcher.find()) {
    // 非针器械 + 针折算(needleQty÷5)
}
```

而全局小件关键词清单（`needle.keywords`）只收录 8 种小件针：**克氏针/银质针/内热针/车针/拔髓针/扩大针/根扩针/卷棉子** —— **气腹针不在其中**（与用户口径一致）。但关键词清单只用于「是否交给小件规则」的旁路判断，并不能阻止针数量拆分本身，于是「气腹针1」被误拆。

### 放大因素：`extractLastNumber` 只取最后一个数字

拆分逻辑用 `extractLastNumber(beforeNeedle)` 计算非针器械数，对「戳卡**4**转换器**1**气腹」只取到 1（丢失戳卡 4 件），导致 6 件 → 2 件的严重少计。

### 截图中「针盒针5合1」特色规则命中为旧构建行为

用户截图显示「平房人民针盒针5合1免包材」命中穿刺器5气腹针1 —— 经核实这是**旧构建**（2026-09-02 针盒针关键词修复部署前）：现构建规则关键词为 `["针","缝合针"]` + `exact_token`，「气腹针1」中「针」前邻 CJK「腹」不构成词边界，**已不会命中**（本地模拟确认「混合模式未命中特色规则」）。

## 共性排查

扫描全部严格医院原始账单，包名含「气腹针N」（数字紧邻）的涉及 **5 家医院**：

| 医院 | 包名示例 |
|------|----------|
| 平房区人民（9月新账） | 戳卡4转换器1气腹针1、穿刺器5气腹针1 |
| 呼兰区红十字 | 戳卡5气腹针1转换器1/z2565、巾钳子4转换器1气腹针1/Z2030 |
| 哈尔滨市第二医院 | 气腹针-1/z1030（横线形，不触发拆分，无影响） |
| 哈尔滨市第五医院 | 外科气腹针-2件/双/Z7526（横线形，无影响） |
| 省医院香坊/中医三院电力 | 气腹针-1/z1026、气腹针-1/z7530（横线形，无影响） |

即「气腹针N」紧凑写法均会被误拆，**是共性问题**；横线写法（气腹针-1）天然不触发。

其他针类（弯针×266、排针×18、探针×10 等）是否折算属各院口径，基线对账均通过，**不在本次修复范围**（严禁过度工程）。

## 修复内容

`PricingEngine.java` 针数量拆分入口：跳过「气腹针N」匹配（取第一个非气腹针的 针N 匹配；全部为气腹针则不拆分），与既有 `吸脂针长型号` / `W9050` 排除先例一致：

```java
// 气腹针是腹腔镜全价器械（非 5 合 1 小件，全局小件关键词亦未收录），
// 「气腹针N」的 N 为实件数，不参与针数量拆分
boolean foundNeedleQty = false;
while (needleQtyMatcher.find()) {
    int matchStart = needleQtyMatcher.start();
    if (matchStart >= 2 && "气腹".equals(packName.substring(matchStart - 2, matchStart))) {
        continue;
    }
    foundNeedleQty = true;
    break;
}
```

拆分点由 `split("针\\d+", 2)` 改为按选中匹配位置 substring（无气腹针时行为与原逻辑完全一致）。

新增回归测试 2 个（`PricingEngineTest`）：
- `veressNeedleCountIsNotFoldedByGlobalNeedleSplit`：戳卡4转换器1气腹针1 ×6 不出现任何折算 note
- `nonVeressNeedleCountStillSplitsByGlobalNeedleRule`：针10 仍正常拆分（防过度排除）
